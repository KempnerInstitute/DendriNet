Component catalogue

A model is an encoder, a core network and a decoder (see Model architecture), each selected by a name in the configuration. This page lists the core types, the encoder and decoder types, and the registries through which code adds new components. The other lists of names (synapse types, activations, training strategies, datasets, analyzers and more) live on the pages that explain them; Other component lists links to them.

Component names are resolved when the component is built, not when the configuration loads, so a misspelled name passes the loader and fails when the model, dataset or trainer is built. dendritic-train --validate-only builds every component without training and reports such errors.

Core types

model.core.type selects the core. Names are case-insensitive. dendritic_modeling.networks.architectures.factory.get_available_architectures() returns every built-in name and every registered extension.

Population networks

model.core.type

Core

Configuration

population_network

Layers of named excitatory and inhibitory populations with explicit, directed connections, feedforward or recurrent; each population has its own morphology and options. See Population networks.

model.core.population_network

Structured E/I cores

Stacks of excitation/inhibition (E/I) layers: each layer has an excitatory population of dendritic trees and an optional inhibitory population, wired by synapse counts per branch. They read the sections model.core.architecture, connectivity, transfer, morphology, sparsity, reactivation, blocklinear and implementation; a recurrent structured core also reads dynamics, synapse_types, dendritic_spikes, soma_feedback and recurrent_ei. See Structured E/I cores, and Integration modes for the integration rules.

model.core.type

Core

einet

Structured E/I core whose integration rule comes from model.core.morphology (use_shunting, default true).

dendritic_shunting

Shunting (divisive) inhibition.

dendritic_additive

Raw additive (subtractive) inhibition.

dendritic_normalized_additive

Additive inhibition with voltage normalization.

dendritic_signed

Signed weights (weight_transform: identity) in separate excitatory and inhibitory synapse banks, combined additively.

dendritic_mlp

Signed weights in one synapse bank per branch that reads the excitatory and inhibitory inputs together, combined additively.

flat_shunting, flat_additive, flat_normalized_additive, flat_signed, flat_mlp

The dendritic_* type of the same suffix with a flattened tree: the same number of branch compartments, all attached directly to the soma.

Recurrent unified E/I cores

Layered E/I networks with an excitatory and an optional inhibitory population per layer, feedforward or recurrent, configured by model.core.unified_ei. See Unified E/I core.

model.core.type

Core

unified_ei (alias ei_unified)

Each population’s options set its integration rule and morphology. The names ei_net and unified_einet build the same core with a deprecation warning.

rnn_dendritic_shunting, rnn_dendritic_additive, rnn_dendritic_normalized_additive

unified_ei with shunting, raw additive or normalized additive integration set on every population.

rnn_flat_shunting, rnn_flat_additive, rnn_flat_normalized_additive

As the rnn_dendritic_* types, with branch_factors: [1] on every population.

Pass-through

identity (alias none) passes the encoder output to the decoder unchanged; it reads no section.

Names that are not core types

The architecture factory also builds encoder, decoder and Python building blocks: mlp, effectivematchedparammlp, alexnet, cnn, cnn_down, cnn_downsample, cnndownsample, cnn_up, cnn_upsample, cnnupsample, mlpautoencoder, mlpvariationalautoencoder, cnnautoencoder, cnnvariationalautoencoder, pathway_router and router. They take flat parameters that model.core cannot express, so model.core.type set to one of them raises an error that names the alternatives (affine_mlp for a plain MLP core, point_mlp for a matched control).

Encoder and decoder types

model.encoder.type and model.decoder.type select the encoder and the decoder; their options go under model.encoder.params and model.decoder.params. Names are case-insensitive. The loader rejects an option that the selected type does not read, unless it holds its default value.

Encoders:

model.encoder.type

Encoder and the options it reads

identity (alias none)

Passes the input through. input_dim and input_shape are set from the dataset by dendritic-train.

pathway_router (alias router)

Routes the input features into separate pathways and concatenates their outputs. router_mode (fixed or learned), pathway_groups (input feature indices of each pathway; by default the features are split evenly into n_pathways groups), shared_indices (features every pathway receives), pathway_dim or pathway_dims (output width of each pathway; by default its number of features), router_activation (an activation type, default none), and for learned routing learned_router_temperature and learned_router_init_scale.

mlpautoencoder, mlpvariationalautoencoder

The encoder half of a multilayer-perceptron (variational) autoencoder: encoder_hidden_dims, latent_dim, decoder_hidden_dims, activation.

cnnautoencoder, cnnvariationalautoencoder

The encoder half of a convolutional (variational) autoencoder: encoder_hidden_dims, latent_shape, decoder_hidden_dims, activation.

Decoders:

model.decoder.type

Decoder and the options it reads

MLP

A multilayer perceptron from the core output to output_dim (default 10) outputs: hidden_dims (default [16]; [] gives a single linear readout), activation (an activation type, default relu), input_normalization (none or layer_norm), input_norm_eps (default 1e-5) and output_init (default, zero, xavier, xavier_zero_bias or xavier_uniform).

identity (alias none)

Passes the core output through. A written output_dim must equal the core output size.

The decoder’s input_dim is always set from the core output size. Other names, such as linear or the CNN building blocks, load but fail when the model is built.

Pretraining autoencoder encoders

An autoencoder encoder is trained before the main phase. With training.encoder_pretraining.epochs positive, dendritic-train first trains the whole autoencoder to reconstruct the training inputs and keeps the state with the lowest validation loss; its encoder then feeds the core. A trained autoencoder can instead come from model.initial_checkpoint (with epochs: 0). Without either, the run raises.

model:
  encoder:
    type: mlpautoencoder
    params: {encoder_hidden_dims: [256], latent_dim: 32, decoder_hidden_dims: [256]}
training:
  encoder_pretraining:
    epochs: 50                # 0 (default): no pretraining
    batch_size: 256
    loss_function: mse        # mse | log_mse | bce | vae_elbo (variational only)
    optimizer: adam
    learning_rate: 0.001
    weight_decay: 0.0
    early_stopping: true
    patience: 10
    grad_clip_value: null
    freeze_encoder: true      # false: the encoder trains with the model

With freeze_encoder (the default) the encoder receives no gradients in the main phase and stays in evaluation mode, so a variational encoder returns its latent mean; the run directory holds the pretraining losses in encoder_pretraining/summary.json, and the model checkpoints contain the encoder. Pretraining runs in single-process training: start a DDP run from the checkpoint of a single-process run, and use another encoder with FSDP. A positive epochs with an encoder that is not an autoencoder raises. dendritic-train and the FSDP entry point check these requests for the built-in encoder types before they create the run directory, so a rejected request leaves no files behind; an encoder that a plugin builds is checked once the model is built.

Extension registries

Code outside the library adds named components by registering them. A registered name is then accepted wherever the configuration selects that kind of component.

A core builder, called as builder(parameters, input_dim=..., suffix_input_dim=...). It returns an nn.Module with an output_dim attribute; parameters is the typed model.core section.

model.core.type

Built-in names are reserved; an existing extension name needs allow_override=True.

The estimator class of one information estimation method.

Only the members of EstimationMethod; registering replaces the built-in estimator of that method.

Registrations run in the process that uses them. A package makes them available to every DendriNet command and script by declaring them as a plugin, which the library loads before the first configuration, whenever a registry meets a name it does not know and whenever a registry lists its names; plugins can also register configuration sections, model builders and additive integration rules (Extending DendriNet).
