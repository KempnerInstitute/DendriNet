Available Components

Quick reference of all implemented components and their configuration strings.

Extension Registries

Most built-in components below are selected by YAML strings. For project-local extensions, use the registry APIs so additional components can be added without editing central dispatch chains:

Family

Registry API

Selection path

Architecture / core

dendritic_modeling.networks.architectures.register_architecture

model.core.type or direct get_architecture(...) calls

Optimizer

dendritic_modeling.training.optimizers.register_optimizer

training.main.optimizer.name

Loss

dendritic_modeling.training.loss.register_loss_function

trainer loss_function / configured loss name

Dataset

dendritic_modeling.datasets.register_dataset

data.task.dataset

Analyzer metadata

dendritic_modeling.analysis.register_analyzer

metadata/discovery only; execution remains in AnalysisManager

Built-in architecture names are reserved and cannot be shadowed by extension registrations. This keeps existing experiments reproducible while allowing project-local components to be introduced cleanly.

Extension workflow:

Component type

Add

Keep stable

Architecture or layer family

Register with register_architecture and expose a YAML type string

Existing model.core.type aliases and typed-config defaults

Synapse or receptor kinetics

Add a synapse_types entry or a typed-synapse implementation behind the recurrent population path

Neuron or soma dynamics

Rate-mode behavior and state to/detach/clone contracts

Analyzer

TopK Variants

Set via model.core.sparsity.type. Canonical values are:

Type

Description

standard

Deterministic top-K mask

stochastic

Soft top-K with temperature

variance

Variance-aware selection

dense_to_sparse

Dense/high-K warmup followed by scheduled pruning to the configured synapse count; annealed_topk is an alias

deepst

Dynamic rewiring with density targets

indexed

Fixed-index sparse synapses that store only out_features x K weights plus integer presynaptic indices

indexed_dynamic

Candidate-pool sparse TopK; stores out_features x C candidate weights and dynamically selects K active candidates per forward pass

indexed_rewire

Fixed-budget indexed sparse synapses with adaptive-quantile turnover; stores only out_features x K weights and periodically replaces weak same-row synapses with newly sampled allowed inputs

topk is retained as an alias for standard. annealed_topk is retained as a readable alias for dense_to_sparse.

Weight Transforms

Set via model.core.morphology.weight_transform:

softplus – always positive, smoother gradient (default structured EI / recurrent setting). exp – always positive, sharp exponential parameterization. relu – non-negative, can be exactly zero. identity – signed weights (for dendritic_mlp).

For biologically constrained recurrent runs, pair a positive transform (exp or softplus) with allow_self_recurrence: false in the population config to remove same-population autaptic feedback.

Transformer replacement distillation

Recurrent protocols

Small structural interfaces for trainer-facing sequence cores and one-step recurrent dendritic populations.

Population Network Layers

Set model.core.type: population_network to define layers with more than one named cell population. Each population owns its own PopulationConfig payload, so morphology and dynamics can differ by population.

The current two-population E/I feedforward layer is the simple special case:

model:
  core:
    type: population_network
    population_network:
      layers:
        - name: layer0
          readout_population: e
          population_defaults:
            ff_excitatory_synapses: 4
            ff_inhibitory_synapses: 2
            rec_excitatory_synapses: 0
            rec_inhibitory_synapses: 0
            reactivate: true
          populations:
            - name: i
              polarity: inhibitory
              n_neurons: 16
              branch_factors: [1]
            - name: e
              polarity: excitatory
              n_neurons: 64
              branch_factors: [3, 2]
          connections:
            - source: input
              target: i
            - source: input
              target: e
            - source: i
              target: e

For independent transfer streams, enable the transfer layer and use explicit external source names. source: input is the default stream; source: input_e and source: input_i refer to the excitatory and inhibitory tensors returned by TransferLayer on the first layer:

model:
  core:
    type: population_network
    population_network:
      use_transfer: true
      transfer_params:
        input_mode: 0
        independent_pathways: true
        excitatory_dim: 392
        inhibitory_dim: 392
      layers:
        - name: layer0
          readout_population: e
          population_defaults:
            ff_excitatory_synapses: 4
            ff_inhibitory_synapses: 2
            rec_excitatory_synapses: 0
            rec_inhibitory_synapses: 0
          populations:
            - name: i
              polarity: inhibitory
              n_neurons: 16
              branch_factors: [1]
            - name: e
              polarity: excitatory
              n_neurons: 64
              branch_factors: [3, 2]
          connections:
            - source: input_e
              target: i
            - source: input_e
              target: e
            - source: input_i
              target: e
            - source: i
              target: e

Same-step population-to-population connections must be directional and acyclic. For example, i -> e is allowed, but e -> i plus i -> e in the same layer and same timestep raises a config error. Bidirectional population interactions are supported with timing: delayed on recurrent layers, where they use previous-timestep outputs instead of creating an algebraic loop.

For multiple layers, each layer defines its own population graph. source: input remains the compatibility shorthand for the previous layer’s readout stream. Prefer explicit qualified sources when a later layer should receive specific earlier populations:

connections:
  - source: layer0.e0
    target: i1
  - source: layer0.e0
    target: e1
  - source: layer0.i0
    target: e1
  - source: i1
    target: e1

Same-step qualified sources must come from earlier layers. Delayed qualified sources are allowed on recurrent target layers and use previous-timestep population outputs.

If input_projection_dims is combined with use_transfer: true, the projection applies to input/input_e. input_i keeps the inhibitory dimension produced by TransferLayer.

Canonical examples cover the main cases: population_network_feedforward.yaml for the standard E/I layer, population_network_heterogeneous_feedforward.yaml for multiple populations with distinct morphologies in one feedforward layer, population_network_two_layer.yaml for explicit cross-layer routing, population_network_recurrent_pyr_pv_sst.yaml for delayed recurrent microcircuits, and the population_network_synapse_types_*, population_network_spiking.yaml, and population_network_soma_feedback.yaml files for biophysical recurrent options.

Analysis Modules

Each enabled under analysis.<module_name>.enabled:

Preferred short names in YAML are performance, information, representation_accessibility, ablation, and correlation. The longer *_analysis names are accepted as aliases.

Available modules: performance, information, representation_accessibility, ablation, correlation, weight, synapse_turnover, noise_perturbation, compartment_statistics, compartment_snr, multiplicative_gain, routing, receptive_field, adversarial_robustness, single_layer_contribution, synaptic_activation, branch_activation, reactivation_dynamics, inhibitory_specialization, jacobian_spectrum, dendritic_timetraces, local_rule_components, spike_train.

representation_accessibility captures post-gate soma populations from stacked feedforward population networks. It provides validation-to-test Ridge and MLP probes, label-independent matched-width projections, joint population class information, and separate per-soma scalar information summaries.

Information Analysis Components

Set via analysis.information.params.selection.components.

Component

Implemented metrics and notes

basic

I(E; C), I(I; C), I(Vb; C), I(Vout; C), I(E, I; C), and I(Vinf; C) when include_vinf is enabled

pairwise

I(E; I), I(E; Vout), I(I; Vout), I(E; Vb), I(I; Vb), I(Vb; Vout), plus analogous Vinf pairwise terms when enabled

conditional

I(E; I | C), I(E; Vout | C), I(I; Vout | C), I(E; Vb | C), I(I; Vb | C), I(Vb; Vout | C), and Vinf variants when enabled

ablation_aligned

Adds ablation-mirroring CMI terms including I(Vout; C | E), I(Vout; C | I), I(Vout; C | Vb), I(Vout; C | E, I), I(E; C | I, Vb), I(I; C | E, Vb), I(E, I; C | Vb), and no-Vb fallbacks such as I(E; C | I) and I(I; C | E)

upstream_unique_cmi

Adds I(Vb; C | E, I) when Vb exists

gaussian_fisher

Fisher or Gaussian proxy metrics such as I(Vout; C)_fisher and I(Vb; C | E, I)_fisher

layer_proxies

Layer-level derived summaries such as _sum, _union, and topK_sum built from single-branch metrics

pid

Partial information decomposition. Present in config, but currently reserved or disabled

For Vout specifically, the analyzer currently emits I(Vout; C), I(Vout; C | E), I(Vout; C | I), and I(Vout; C | E, I).

Initialization Methods

Set via model.core.sparsity.init_method:

xavier_normal, xavier_uniform, kaiming_normal, kaiming_uniform, orthogonal, normal, uniform, eye.

BlockLinear Initialization

Set via model.core.morphology.dbl_init_method:

analytical_expectation, ei_equivalence, naive, default, mechanism_neutral. The last option is reserved for paired causal controls: with a shared seed it initializes shunting and additive models identically and does not provide mechanism-specific operating-point optimization.
