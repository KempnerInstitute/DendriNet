Configuration Guide

The primary configuration reference is configs/config_exp.yaml. That file lists every parameter accepted by the framework together with its default value and valid options. This page summarises the structure and highlights the most important settings; for the full parameter list, consult the YAML file directly or the Complete Configuration Reference page.

Quick Start

# Standard training
python src/dendritic_modeling/scripts/training/train_experiments.py configs/config_exp.yaml

# With overrides
python src/dendritic_modeling/scripts/training/train_experiments.py \
  configs/config_exp.yaml --output_dir results/my_run --run_name test1

Templates:

  • configs/config_exp.yaml – single-GPU training (complete reference)

  • configs/config_exp_fsdp.yaml – FSDP multi-GPU training

  • configs/sweep_config.yaml – generic parameter-sweep template

Top-Level Structure

experiment:   # seed, profiling, checkpointing
data:         # dataset, processing, dataset-specific params
model:        # encoder, core network, decoder, pretrained_replacement
training:     # encoder + main training, strategies, regularization, pruning, AMP
analysis:     # 20 analysis modules
wandb:        # Weights & Biases logging
outputs:      # run_name, results_dir
distributed:  # mode (none/ddp/fsdp), FSDP tuning knobs

Core Network Types

Set model.core.type to one of:

Type string

Description

dendritic_shunting

Shunting (divisive) inhibition

dendritic_additive

Raw additive (subtractive) inhibition, V = E - I

dendritic_normalized_additive

Additive inhibition with explicit voltage normalization

dendritic_mlp

Dendritic morphology, no E/I sign constraint

point_mlp

Point-neuron MLP baseline (matched params)

einet

Legacy generic E-I type; uses morphology.use_shunting

flat_shunting

Single-branch shunting variant

flat_additive

Single-branch raw additive variant

flat_normalized_additive

Single-branch normalized additive variant

ei_unified

Unified E-I, supports feedforward and recurrent

rnn_dendritic_shunting, rnn_dendritic_additive, rnn_dendritic_normalized_additive

Unified recurrent E-I aliases with shunting/raw-additive/normalized-additive defaults applied

population_network

Canonical notation for feedforward stacks and recurrent microcircuits with named E/I populations, per-population morphology, explicit directed connections, synapse types, spiking soma, and feedback

gru, lstm

Baseline RNNs

vanilla_rnn

Plain point-RNN baseline

mlp

MLP baseline

See Network Architectures for architecture details. For recurrent ei_unified models, the biology-facing configuration now also supports allow_self_recurrence: false inside each population block to disable same-population E->E and I->I self-feedback while keeping cross-population recurrence intact. Structured feedforward EINet configs and recurrent PopulationConfig blocks now share the same positive-weight default (weight_transform: softplus). Use weight_transform: exp explicitly when you want the sharper positive-conductance parameterization.

Shunting/additive precedence is intentionally path-specific but canonical: dendritic_shunting / dendritic_additive / dendritic_normalized_additive / flat_* types define the effective feedforward mode, and contradictory model.core.morphology.use_shunting or use_additive_normalization values are warned about and overwritten. The generic einet type is the explicit escape hatch when you want morphology flags to choose the mode. For recurrent rnn_* aliases, the alias is applied to every excitatory and inhibitory PopulationConfig block; rnn_flat_* also forces branch_factors: [1]. Plain ei_unified and population_network keep population-level fields as their source of truth. Transformer replacement builders follow the same model.core.type alias when one is present, otherwise they read model.core.morphology.use_shunting.

For additive modes, prefer reactivation.init_policy: "occupancy_quantile". When an additive YAML config omits reactivation.init_policy, typed config loading chooses occupancy_quantile by default; explicit policies such as analytical or fixed are preserved for reproduction. The legacy spelling quantile is accepted as a deprecated alias for occupancy_quantile. When you use a data-driven gate init policy (occupancy_quantile or empirical), each run also writes init_gate_stats.json into its run directory. Use that artifact to confirm that reactivation gates were initialized sensibly before trusting the run.

Config loading validates structural model contracts before model creation. For example, invalid input_mode values, impossible per-layer synapse-list lengths, duplicate population names, unknown connection endpoints, delayed population edges without recurrent: true, and same-step population cycles raise a clear ConfigValidationError from load_config. Training-stability and scientific plausibility checks remain in the training validators so older experiments are not rejected for warning-level choices.

Canonical Config Choices

Use these defaults when writing new configs. They keep the code path modular and make feedforward, recurrent, additive, shunting, local-learning, and sweep runs easier to compare.

Decision

Preferred setting

Rationale

Architecture notation

model.core.type: population_network

One schema covers original E/I layers, heterogeneous populations, multilayer feedforward routing, delayed recurrent edges, spiking, typed synapses, and feedback.

Shunting vs additive

Choose the type or per-population use_shunting directly; use dendritic_normalized_additive only when normalization is the intended model

Raw additive and normalized additive are scientifically different models, so normalization should be explicit.

Gate initialization

reactivation.init_policy: occupancy_quantile

Data-driven gate placement is the fairest default across shunting, raw additive, normalized additive, shallow, and deep networks.

Positive conductances

weight_transform: softplus

Keeps conductances positive with smoother gradients than exp.

Developmental sparsity

topk_type: dense_to_sparse

Lets all weights receive gradient early, then prunes to the target sparse budget on a controlled schedule.

Multilayer routing

Qualified sources such as layer0.e0 and layer0.i0

Avoids hidden broadcasting assumptions and supports multiple readout streams from earlier layers.

Recurrence

timing: delayed on a recurrent layer

Delayed edges read previous-timestep state and avoid same-step algebraic loops.

Sweeps

Dot paths under model.core.population_network

The same field names work for training, sweeps, and analysis metadata.

Training Strategies

Set training.main.strategy to one of:

standard, fa, dfa, shunting_fa, shunting_dfa, local_ca, freeze_layers, freeze_branches, freeze_branch_kl, voltage_stabilization, homeostatic_control, multi_stage, recurrent

Strategy-specific configuration usually lives under training.main.strategies.<name>. Local credit assignment uses the direct path training.main.learning_strategy_config for 3f/4f/5f local rules and the separate stdp trace rule. See Training Strategies for details.

DataLoader options live with the shared training fields and are honored by both the standard trainer and FSDP script:

training:
  main:
    common:
      batch_size: 512
      num_workers: null          # null = trainer default / auto
      pin_memory: null           # null = auto by device
      persistent_workers: null   # requires num_workers > 0
      prefetch_factor: null      # requires num_workers > 0

Loss Functions

Set training.main.common.loss_function (or training.encoder.common.loss_function) to:

mse, log_mse, ce, bce, cat_nll, vae_elbo, neg_cos_sim, log_adj_neg_cos_sim

Datasets

Set data.dataset_name to one of:

  • Standard: mnist, fashion_mnist, cifar10, imagenet, mnist_modulo10, cifar10_modulo10, double_cifar10_contextual_mod10, double_mnist_contextual_mod10

  • Synthetic: correlated_gaussian, nonlinear_interaction, linear_separable, nonlinear_separable, block_correlated, balanced_information, contextual_stream_gain_shift, poisson_generator, multixor, orientation_bars, orthonet

  • Sequence: sequential_mnist, copy_task, adding_problem, variable_delay_dms, multi_frequency, hierarchical_temporal, context_dependent_decision, context_dependent_decision_hard, context_dependent_decision_positive, context_dependent_decision_hard_positive, switching_context_decision, switching_context_decision_positive, timescale_generalization, timescale_generalization_positive, odr_generalization, odr_generalization_positive, romo_delay_comparison, romo_delay_comparison_positive, gain_modulated_contextual_comparison, gain_modulated_contextual_comparison_positive, lorenz, lorenz_sequence, switching_lds, multi_sine_forecast, stringer_v1

Dataset-specific parameters go under data.dataset_params.<name>. See Datasets for details.

For ImageNet with a pretrained torchvision backbone, use the pretrained transform preset and keep fake-data fallback disabled for real runs:

data:
  dataset_name: "imagenet"
  base_dir: "/path/to/imagenet"
  processing:
    flatten: false
    normalize: true
  dataset_params:
    imagenet:
      transform_preset: "pretrained"
      allow_fake_data: false
      allow_flatten_materialize: false

For shunting E-I models with positive weight transforms, keep the tensors that enter the first shunting layer non-negative. If preprocessing uses normalize: true, either disable normalization for that run or set model.core.transfer.output_activation to a nonnegative activation such as "relu" so the transfer-layer outputs remain non-negative.

Analysis Modules

Each module lives under analysis.<module_name> with enabled and training flags:

analysis:
  runtime:
    training:
      mode: "auto"
      batch_size: 256
      num_workers: 4
      pin_memory: true
      max_batches: null
      max_samples: null
      materialize_threshold_mb: 1024
    final:
      mode: "auto"
      batch_size: 256
      num_workers: 4
      pin_memory: true
      max_batches: null
      max_samples: null
      materialize_threshold_mb: 1024
  performance:
    enabled: true
    training: true    # run every epoch
    training_splits: ["valid"]
    final_splits: ["train", "valid", "test"]
  information:
    enabled: true
    training: false   # run after training only

analysis.runtime is the shared dataset-iteration policy for all analysis modules. Use mode: "stream" for large datasets that should not be fully materialized on the device, and use max_samples for expensive analyses that still accumulate tensors on CPU. If you want older small-dataset single-GPU behavior for hook-based analyses, set mode: "materialize": the runtime will use one full batch again when the dataset supports slicing. Analyzers may temporarily move the model to the requested analysis device, but the original device and train/eval mode are restored automatically after the analysis finishes. For most runs, keep the default mode: "auto": it behaves like the old path on small datasets and switches to streaming only when the dataset estimate is large. If you omit analysis.runtime entirely, non-distributed runs default to the old materialize behavior for backward compatibility, while DDP/FSDP runs keep the generic auto default. The pin_memory flag is also interpreted per device: CPU analysis disables it automatically even if the shared runtime block leaves it set to true.

Preferred short names are performance, information, ablation, and correlation. The longer *_analysis aliases are still accepted for backward compatibility.

Available modules: performance, information, correlation, ablation, synapse_turnover, noise_perturbation, weight, single_layer_contribution, synaptic_activation, branch_activation, compartment_statistics, compartment_snr, multiplicative_gain, receptive_field, adversarial_robustness, routing, reactivation_dynamics, inhibitory_specialization, jacobian_spectrum, dendritic_timetraces.

See Analysis for per-module parameter details.

Backward compatibility:

  • Older configs using performance_analysis instead of performance still load.

  • Older performance-only training_runtime / final_runtime blocks still load and are migrated into the shared analysis.runtime structure.

Pretrained Backbone Replacement

Replace one or more layers of a pretrained torchvision backbone (e.g. AlexNet, VGG) with an EINet core. The backbone is loaded once and split into three segments:

  • prefix (encoder): all layers before the replacement range

  • core: the dendritic EI network that replaces the removed layers

  • suffix (decoder): all layers after the replacement range

When model.pretrained_replacement.enabled is true, the legacy model.encoder and model.decoder sections are ignored.

model:
  pretrained_replacement:
    enabled: true
    backbone: "alexnet"                    # torchvision model name
    weights: "IMAGENET1K_V1"               # pretrained weights (null = random init)
    input_shape: [3, 224, 224]

    # Layers to replace (inclusive range).
    # Use list_backbone_layers("alexnet") to see all available names.
    replace:
      start: "classifier.4"                # fc7 Linear
      end: "classifier.5"                  # fc7 ReLU

    # Drop layers entirely (e.g. Dropout that is not useful with EI nets).
    omit_layers: ["classifier.0", "classifier.3"]

    # Freeze/train policy for encoder and decoder segments.
    trainability:
      encoder:
        mode: "frozen"                     # freeze conv backbone + fc6
      decoder:
        mode: "trainable"                  # train final classifier

  core:
    type: "einet"
    architecture:
      excitatory_layer_sizes: [4096]       # must match suffix input dim
      # ... rest of EINet config ...

Alternative pretrained-replacement cores:

  • hierarchical_dendritic_tensor_map Flattens the prefix tensor, runs a newly initialized EINet-style hierarchical dendritic core, then projects to the suffix input dimension when needed. Use this as the baseline/control for late classifier-adjacent replacements where the suffix expects flat input. The pretrained part is the surrounding backbone split, not the tensor-map core itself.

  • hierarchical_dendritic_conv Uses local spatial patches (core.spatial.kernel_size/stride/padding) and a shared hierarchical dendritic core to produce a spatial feature map for the suffix. Use this for convolutional suffixes that still expect spatial input.

Current spatial-replacement scope:

  • hierarchical_dendritic_tensor_map is intended for flat suffixes or small spatial maps that can be flattened safely.

  • hierarchical_dendritic_conv preserves the prefix/suffix spatial contract, but its local geometry is set by core.spatial.*; it does not infer the effective receptive field of an arbitrary multi-layer CNN block automatically.

  • Sequential backbones such as AlexNet and VGG are the primary supported cases.

Learning rates for the prefix and suffix are controlled in the training config:

training.main.common.param_groups.encoder_lr    # prefix LR (0.0 = frozen)
training.main.common.param_groups.decoder_lr    # suffix LR

To discover valid layer names for a backbone, use the list_backbone_layers utility:

from dendritic_modeling.networks.architectures.classical.pretrained import (
    list_backbone_layers,
)
print(list_backbone_layers("alexnet"))
# ['features.0', 'features.1', ..., 'avgpool', 'classifier.0', ..., 'classifier.6']

Scope: The current splitter linearizes nn.Sequential containers. This works for AlexNet, VGG, and coarse splits of ResNet (e.g. at avgpool or fc). Replacing layers inside residual blocks requires an FX-graph backend (planned).

The runnable examples page includes configs/examples/alexnet_fc7_dendritic_500.yaml, which replaces AlexNet fc7 with a 500E-only dendritic tensor-map core. See Runnable Config Examples for all four primary example configs.

Additional pretrained replacement configs:

  • configs/vision/alexnet_k1_einet_single.yaml — replace fc7 only (K=1), single-GPU / non-DDP

  • configs/vision/alexnet_k1_einet_ddp.yaml — same K=1 replacement configured for DDP launch

  • configs/examples/pretrained_alexnet_fc.yaml — tensor-map pretrained replacement around AlexNet FC layers

  • configs/examples/pretrained_alexnet_conv.yaml — spatial pretrained replacement example for AlexNet conv/feature maps

  • scripts/test_pretrained_training.sh — generates a temporary 1-epoch AlexNet smoke config

Transformer MLP / FFN Replacement

Transformer replacement follows the same idea as AlexNet replacement: define the source network and replacement sites, then define the dendritic replacement with model.core. The source-network block is model.transformer_replacement instead of model.pretrained_replacement because transformer MLPs live inside decoder blocks rather than in a flat nn.Sequential layer list.

DeepSeek-V3/R1-style models are a natural first target because the first three decoder blocks use dense FFNs before the later MoE blocks. Public DeepSeek-V3 configs use hidden_size=7168, intermediate_size=18432, and first_k_dense_replace=3. The dense gated FFN parameter count per layer is approximately 3 * hidden_size * intermediate_size.

model:
  transformer_replacement:
    enabled: true
    model_name: deepseek-ai/DeepSeek-V3
    layers: [0, 1, 2]
    target_module: mlp
    layers_attr: model.layers
    input_transform: signed_split
    model_kwargs:
      device_map: auto
      torch_dtype: auto

  core:
    type: dendritic_ffn
    architecture:
      excitatory_layer_sizes: [512]
      excitatory_branch_factors: [3, 3]
    connectivity:
      ee_synapses_per_branch_per_layer: [40]
    morphology:
      use_shunting: true
      weight_transform: softplus
    sparsity:
      type: indexed_dynamic
      temperature: 0.5
    indexed:
      candidate_size: 256
      selection: stochastic
      seed: 42

Training the replacement is configured separately under training.transformer_replacement. The first supported training mode is layerwise distillation: freeze the teacher MLP, feed hidden states through the original MLP, and train the dendritic module to match that MLP output.

\[\mathcal{L}_{\mathrm{distill}} = \frac{1}{|\mathcal{B}|} \sum_{h \in \mathcal{B}} \left\|D_{\theta}(h) - \mathrm{MLP}_{\mathrm{teacher}}(h)\right\|_2^2.\]
training:
  main:
    optimizer:
      name: adamw
      lr: 3.0e-4
      weight_decay: 0.01

  transformer_replacement:
    enabled: true
    mode: layerwise_distillation
    teacher_source: hf_text          # synthetic_mlp | hidden_cache | hf_text
    train_target: replacement_only
    layers: [0, 1, 2]
    device: cuda
    dtype: bfloat16
    sequence_length: 128
    batch_size: 1
    max_steps: 1000
    eval_every: 100
    loss: mse
    save_dir: results/deepseek_v3_dendritic_mlp_distillation
    text:
      text_path: /path/to/text_corpus.txt
      tokenizer_name: deepseek-ai/DeepSeek-V3
      max_tokens: 1000000

Run the distillation trainer with:

PYTHONPATH=src:$PYTHONPATH python -m \
  dendritic_modeling.scripts.training.train_transformer_replacement \
  configs/examples/deepseek_v3_mlp_dendritic_replacement.yaml

For a quick local learning check that does not load a Hugging Face model, use configs/examples/transformer_replacement_synthetic_distillation.yaml.

Apply the YAML-style config to a loaded Hugging Face model:

from dendritic_modeling.networks.architectures.transformer import (
    apply_transformer_replacement_config,
    load_transformer_with_dendritic_replacements,
)

model, records = load_transformer_with_dendritic_replacements(
    config.model.transformer_replacement,
    config.model.core,
)

# Or, if the model has already been loaded:
records = apply_transformer_replacement_config(
    model,
    config.model.transformer_replacement,
    config.model.core,
)

Important replacement parameters:

dendritic_units

Number of dendritic soma units in the replacement bottleneck.

branch_factors

Dendritic morphology, distal-to-soma. [3, 3] means each soma receives three proximal branches and each proximal branch receives three distal branches.

synapses_per_branch

Number of active presynaptic features per dendritic branch.

topk_type

standard, stochastic, variance, dense_to_sparse, and deepst preserve the dense-score/dynamic behavior of the previous DendriNet TopK family. dense_to_sparse starts dense or high-K and anneals to the configured synapse count; annealed_topk is an alias. indexed stores only exactly active fixed synapses. indexed_dynamic stores a larger candidate pool and dynamically selects the active K from that pool, which is the recommended DeepSeek-scale compromise.

sparsity.dense_to_sparse

Developmental pruning schedule for topk_type: dense_to_sparse. Common fields are initial_density or initial_k, start_step, end_step, update_interval, schedule (linear, cubic, cosine, or step), freeze_on_end, and prune_metric.

sparsity.indexed.candidate_size

Candidate-pool size C for indexed_dynamic. Stored synapse parameters scale as out_features * C instead of out_features * input_features.

input_transform

Use signed_split for transformer hidden states. It maps x to [ReLU(x), ReLU(-x)], allowing positive dendritic conductances to encode signed residual-stream features.

Recommended experimental order:

  1. Patch one layer only and confirm a forward pass.

  2. Freeze the original model and distill the dendritic replacement against the original MLP output for that layer.

  3. Evaluate perplexity with layer 0 replaced.

  4. Repeat for layers [0, 1] and then [0, 1, 2].

Template config: configs/examples/deepseek_v3_mlp_dendritic_replacement.yaml.

Recurrent Networks

Any E-I type (dendritic_shunting, dendritic_additive, einet) becomes recurrent when connectivity.rec_* synapse counts are nonzero. Recurrence is controlled solely by these counts; no separate enabled flag is needed:

model:
  core:
    type: dendritic_shunting       # same type as feedforward
    architecture:
      excitatory_layer_sizes: [64]
      excitatory_branch_factors: [3, 3]
    connectivity:
      ee_synapses_per_branch_per_layer: [12]
      ie_synapses_per_branch_per_layer: [6]
      # Recurrent synapse counts (nonzero = recurrent)
      rec_ee_synapses_per_branch: [8]   # E->E recurrent
      rec_ie_synapses_per_branch: [4]   # I->E recurrent
      rec_ei_synapses_per_branch: [8]   # E->I recurrent
      rec_ii_synapses_per_branch: [4]   # I->I recurrent
    transfer:
      input_mode: 1
      inhibitory_mode: "first"     # none, first, all
    # morphology, sparsity, reactivation as usual...

    recurrent_ei:                  # temporal params only
      output_mode: last            # last, all, mean
      use_transfer: true           # default true (set false to bypass TransferLayer)
      dt: 1.0
      tau_base: 50.0               # scalar or per-layer list
      tau_ratio: 3.0               # scalar or per-layer list

training:
  main:
    strategy: recurrent

For full per-layer, per-population control use core.type: ei_unified with the unified_ei config instead. For baseline RNNs use model.core.type: gru (or lstm, vanilla_rnn). See Network Architectures for full details.

Named Cell Types

The recurrent extensions use a few related terms that are easy to mix up:

Term

Where it is defined

What it means

Population network

model.core.type: population_network and model.core.population_network

The canonical feedforward/recurrent named-population backend. It owns ordered layers, populations per layer, directed source-target connections, readout population, timestep, and output mode.

Named population

population_network.layers[].populations

One named dendritic population, such as pyr, pv, or sst. It defines how many neurons that population has, whether it is excitatory or inhibitory, and what morphology/config overrides it uses.

Population connection

population_network.layers[].connections

A source-target rule between named populations or input streams. It says which population can drive another, whether the edge is same-step or delayed, and can optionally sample a fixed pair-specific mask.

Structured connectivity

model.core.connectivity.structured

A lower-level TopK/DeepST mask on E/I pathways such as ee, ie, and rec_ee. It controls which presynaptic units are eligible for sparse synapses, independent of biological population names.

Synapse type

synapse_types inside population_defaults, a population’s population block, or model.core.synapse_types

A conductance/receptor subtype within an excitatory or inhibitory stream, such as AMPA, NMDA, GABA_A, or a custom continuous class. It changes kinetics, fractions, voltage gates, and reversal potentials; it does not create a new neuron population.

Soma dynamics

dynamics_mode / spike_* or model.core.dynamics

The output rule for each dendritic population. rate is legacy; spike routes the soma through a LIF module.

In short: populations define who the neurons are, population connections define who can talk to whom, structured connectivity defines which individual synapse slots are allowed, synapse types define how a signal is filtered and driven once it arrives, and soma dynamics define how the population emits its output.

For new population-network experiments, use core.type: population_network. It is the single notation for feedforward stacks and recurrent microcircuits: each layer contains named populations, and each edge is an explicit directed connection. timing: same_step is feedforward/default; timing: delayed uses previous-timestep outputs and enables recurrence. Each population is still a dendritic population internally, so the usual PopulationConfig fields can be placed in population_defaults or in an individual population’s population block.

model:
  core:
    type: population_network
    population_network:
      output_mode: last
      layers:
        - name: microcircuit
          recurrent: true
          readout_population: pyr
          connection_seed: 123
          population_defaults:
            ff_excitatory_synapses: 12
            rec_excitatory_synapses: 8
            rec_inhibitory_synapses: 4
            somatic_synapses: true
            reactivate: true
          populations:
            - name: pyr
              polarity: excitatory
              n_neurons: 64
              branch_factors: [3, 3]
            - name: pv
              polarity: inhibitory
              n_neurons: 16
              branch_factors: [1]
            - name: sst
              polarity: inhibitory
              n_neurons: 16
              branch_factors: [1]
          connections:
            - source: input
              target: pyr
            - source: input
              target: pv
            - source: input
              target: sst
            - source: pv
              target: pyr
              timing: delayed
              probability: 0.45
            - source: sst
              target: pyr
              timing: delayed
              probability: 0.25
            - source: pyr
              target: pyr
              timing: delayed
              enabled: false

training:
  main:
    strategy: recurrent

Connection polarity is inferred from the source population or input stream. probability optionally samples a fixed pair-specific mask. Missing probability means dense/all allowed; the target population’s E/I synapse-count fields determine how many active synapses per branch are selected inside the allowed mask.

Each named-population entry has four direct fields plus an optional nested population override:

name

A stable string key used by readout_population, connections, saved routing metadata, and analysis outputs. Use short names such as pyr, pv, sst, or vip when you want biologically motivated labels.

polarity

Either excitatory or inhibitory. This is a circuit-level sign/source classification, not a receptor type. Outgoing edges from excitatory populations enter the target’s E stream; outgoing edges from inhibitory populations enter the target’s I stream.

n_neurons

Number of dendritic neurons in this named population.

branch_factors

The morphology for this population. It overrides any default morphology in population_defaults.

population

Optional dictionary of any PopulationConfig field. Use it when one population should have different synapse counts, time constants, reactivation, structured masks, synapse types, or spiking dynamics from the defaults.

The population_defaults block is copied into every named population before the cell-specific population override is applied. This gives a compact way to share most morphology and integration parameters while changing only the biological identity fields in populations.

population_network uses population_defaults and per-population population blocks as its population source of truth. Top-level feedforward fields such as model.core.morphology.use_shunting are not automatically inherited; set the corresponding PopulationConfig fields, for example use_shunting or weight_transform, directly in population_defaults when they should apply to all named populations.

Synapse Types

Recurrent dendritic populations can optionally split excitatory and inhibitory conductance traces into named synapse types. This is useful for experiments with receptor-like kinetics such as fast AMPA, slower NMDA, GABA-A, and GABA-B, or for continuous conductance classes defined by their reversal potential. The default is disabled, which preserves the original single E trace and single I trace exactly.

Place synapse_types either in a PopulationConfig payload, such as population_network.layers[].population_defaults or a populations[].population override, or at model.core.synapse_types for recurrent EINet-family configs translated through the factory.

Splits raw E/I currents into typed traces before dendritic integration.

You can use biologically named receptors, continuous abstract conductance classes, or both. For example, AMPA/NMDA is a receptor-motivated excitatory split; a custom type named E_rev_0p4 with reversal_potential: 0.4 is a continuous conductance class. The code treats both as named synapse types with kinetics and reversal parameters.

population_network:
  layers:
    - name: recurrent_layer
      recurrent: true
      readout_population: pyr
      population_defaults:
        ff_excitatory_synapses: 12
        ff_inhibitory_synapses: 4
        rec_excitatory_synapses: 8
        rec_inhibitory_synapses: 4
        synapse_types:
          enabled: true
          excitatory:
            - name: AMPA
              fraction: 0.8
              tau_rise: 0.5
              tau_decay: 2.0
              reversal_potential: 1.0
            - name: NMDA
              fraction: 0.2
              tau_rise: 3.0
              tau_decay: 70.0
              reversal_potential: 1.0
              magnesium_block: true
              voltage_scale_mv: 100.0
          inhibitory:
            - name: GABA_A
              fraction: 0.9
              tau_rise: 1.0
              tau_decay: 7.0
              reversal_potential: 0.0
            - name: GABA_B
              fraction: 0.1
              tau_rise: 20.0
              tau_decay: 150.0
              reversal_potential: -0.25
              stp:
                enabled: true
                u0: 0.25
                depression: 0.2

When enabled: true, define both an excitatory list and an inhibitory list explicitly. This keeps a partially specified receptor block from silently falling back to the legacy single-trace path. Fractions are normalized within each polarity. tau: null inherits the population’s existing per-level dendritic time constant, so a single AMPA/GABA_A pair with tau: null is legacy-equivalent. In shunting mode, reversal_potential is used directly in the conductance numerator. In additive mode, typed synapses intentionally support only the normalized legacy reversal convention: excitatory types use reversal_potential: 1.0 and inhibitory types use reversal_potential: 0.0. Use shunting mode for continuous or biophysical reversal potentials such as GABA-B-like negative values. For stability and interpretability, typed reversal potentials use the normalized conductance convention and must lie in [-1.0, 2.0].

For receptor-like dynamics, use tau_rise and tau_decay to create a double-exponential trace. tau remains as a shorthand for a single decay trace. magnesium_block: true applies the standard NMDA-style voltage gate 1 / (1 + Mg * exp(-V_mV / slope) / scale) using the previous level voltage. Because branch voltages are normalized and unitless, the gate first computes V_mV = voltage_scale_mv * V + mg_v_offset. The default voltage_scale_mv: 100.0 makes NMDA-like gates vary across the model’s typical 0 to 1 voltage range while preserving the canonical mg_scale and mg_slope constants. You can also override mg_concentration, mg_scale, mg_slope, and mg_v_offset. nonlinearity can be linear, relu, sigmoid, tanh, or softplus; conductance_power applies a signed power transform to the raw current. The optional stp block adds aggregate short-term utilization/resource dynamics for rate or spike-trace inputs. By default, STP state updates use a detached activity proxy so the current multiplicative factor is differentiable but its history is treated as a fixed state update. Set stp.differentiable_state: true to allow BPTT through the STP state history.

Common definition patterns:

  • Legacy-equivalent: keep enabled: false, or enable one excitatory type and one inhibitory type with tau: null and fractions of 1.0.

  • Biophysical receptors: use names such as AMPA, NMDA, GABA_A, and GABA_B with different rise/decay constants, Mg block, and reversal potentials.

  • Continuous conductance classes: use custom names and vary reversal_potential, tau, nonlinearity, or conductance_power without implying a specific receptor identity.

Spiking Soma Dynamics

Recurrent dendritic populations can optionally replace the rate-valued soma output with leaky integrate-and-fire dynamics. This is configured at the PopulationConfig level for population_network or via model.core.dynamics for recurrent EINet-family configs. The default dynamics_mode: rate preserves the original behavior.

population_network:
  layers:
    - name: recurrent_layer
      recurrent: true
      readout_population: pyr
      population_defaults:
        dynamics_mode: spike
        spike_threshold: 0.6
        spike_reset: 0.0
        spike_tau: 20.0
        spike_refractory_steps: 2
        spike_surrogate_beta: 10.0
        spike_readout: rate       # spikes, rate, membrane
        spike_readout_tau: 20.0

For recurrent EINet-style configs translated through the factory:

model:
  core:
    type: dendritic_shunting
    dynamics:
      mode: spike
      threshold: 0.6
      readout: rate
      tau: 20.0
      refractory_steps: 2

spike_readout: spikes returns binary surrogate-gradient spikes. spike_readout: rate returns a leaky spike trace, which keeps the downstream decoder interface dense and is usually the easiest first training target. spike_readout: membrane returns the LIF membrane before thresholding for ablation and debugging.

Dendritic Spike / Plateau Dynamics

Soma spiking and dendritic spiking are separate switches. Soma spiking changes only the final soma readout. Dendritic spike / plateau dynamics act earlier: after a dendritic level computes its branch voltage and before that voltage is aggregated into the parent level. This makes local branch events propagate toward the soma while preserving the existing branch-factor morphology.

The implementation supports two local event modes:

plateau

A branch emits a surrogate-gradient threshold event and stores it in a leaky plateau trace. The plateau trace then modifies the branch output.

threshold

The branch emits a binary surrogate-gradient local event without a persistent plateau trace.

population_network:
  layers:
    - name: recurrent_layer
      recurrent: true
      readout_population: pyr
      population_defaults:
        dendritic_spikes_enabled: true
        dendritic_spike_mode: plateau       # plateau or threshold
        dendritic_spike_levels: distal      # non_soma, all, distal, proximal, none, or [0, 1]
        dendritic_spike_threshold: 0.7
        dendritic_spike_plateau_amplitude: 1.0
        dendritic_spike_plateau_tau: 20.0
        dendritic_spike_refractory_steps: 5
        dendritic_spike_surrogate_beta: 10.0
        dendritic_spike_propagation: additive  # additive, replace, gated

For recurrent EINet-style configs translated through the factory, the same fields can be nested under model.core.dynamics.dendritic_spikes:

model:
  core:
    type: dendritic_shunting
    dynamics:
      dendritic_spikes:
        enabled: true
        mode: plateau
        levels: non_soma
        threshold: 0.7
        plateau_amplitude: 1.0
        plateau_tau: 20.0
        refractory_steps: 5
        surrogate_beta: 10.0
        propagation: additive

Level indices are distal-to-soma. non_soma and all mean all dendritic levels but exclude the soma; soma spiking is controlled by dynamics_mode: spike and the spike_* fields above. distal means level 0 and proximal means the last dendritic level before the soma. The propagation rule controls how the local plateau/event changes the branch output:

additive

V_modified = V_branch + amplitude * plateau.

replace

V_modified = V_branch * (1 - plateau) + amplitude * plateau.

gated

V_modified = V_branch * (1 + amplitude * plateau).

The recurrent state stores dendritic_spike_plateau, dendritic_spike_refractory, and dendritic_spike_events only when this component is enabled.

Soma-to-Dendrite Feedback

Soma feedback is an optional recurrent component that sends the previous timestep’s soma signal back into selected dendritic levels. The default is off, so existing feedforward and recurrent runs keep the original dendrite-to-soma flow. Because the source is delayed by one recurrent step, the implementation does not introduce a same-timestep circular dependency.

For population_network configs, place the fields in population_defaults or in an individual population’s population block:

population_network:
  layers:
    - name: recurrent_layer
      recurrent: true
      readout_population: pyr
      population_defaults:
        soma_feedback_enabled: true
        soma_feedback_mode: additive      # additive, shunting, gated
        soma_feedback_source: output      # output, voltage, spike_readout
        soma_feedback_levels: non_soma    # non_soma, all, distal, proximal, soma, none
        soma_feedback_strength: 0.15
        soma_feedback_learnable_strength: true
        soma_feedback_per_level: true
        soma_feedback_init_std: 0.01

For recurrent EINet-family configs translated from the structured core config, prefer the canonical model.core.soma_feedback block. The older model.core.recurrent_ei.soma_feedback location is still accepted for backward compatibility:

model:
  core:
    type: dendritic_shunting
    soma_feedback:
      enabled: true
      mode: gated
      source: voltage
      levels: distal
      strength: 0.1

additive adds feedback as a branch-current term. shunting creates a rectified feedback conductance and adds conductance * reversal to the current numerator. gated multiplies the branch output by 1 + tanh(feedback). soma_feedback_init_std defaults to 0.0, making the projection initially no-op; set a small nonzero value when an experiment should start with active feedback.

Spike-specific analysis is available through analysis.spike_train:

analysis:
  spike_train:
    enabled: true
    training: false
    params:
      max_samples: 512
      include_raster: true
      max_raster_samples: 8
      include_per_timestep_rate: true

This analyzer hooks every LIFSoma module and reports firing rate, silent unit/trial fractions, spike-count Fano factors, ISI mean/CV, per-timestep rate, and compact raster events.

Structured Connectivity

Optional hard topology constraints can be added under model.core.connectivity.structured. The existing synapse-count fields still control the TopK budget per branch; the structured mask controls which presynaptic cells are allowed to compete for those TopK slots.

model:
  core:
    type: dendritic_shunting
    architecture:
      excitatory_layer_sizes: [64]
      inhibitory_layer_sizes: [16]
      excitatory_branch_factors: [3, 3]
    connectivity:
      ee_synapses_per_branch_per_layer: [12]
      ie_synapses_per_branch_per_layer: [6]
      ei_synapses_per_branch_per_layer: [8]
      ii_synapses_per_branch_per_layer: [4]

      structured:
        enabled: true
        seed: 123
        pathways:
          ee:                 # E input onto E target cells
            method: fixed_indegree
            indegree: 24
          ie:                 # I input onto E target cells
            method: bernoulli
            probability: 0.35

Pathway names are ee, ie, ei, ii for feedforward/current-layer connections, and rec_ee, rec_ie, rec_ei, rec_ii for recurrent connections. Supported methods are fixed_indegree, bernoulli, and distance. With DeepST, rewiring is constrained to stay inside the structured mask.

Distributed Training

Set distributed.mode to choose the runtime:

distributed:
  mode: ddp            # none | ddp | fsdp
  fsdp:                # FSDP-specific knobs (only used when mode=fsdp)
    sharding_strategy: "FULL_SHARD"
    mixed_precision: true
    cpu_offload: false

  • none — single-GPU, plain python (default)

  • ddp — DistributedDataParallel via torchrun. Best when the model fits on one GPU and you want data-parallel speedup. Supports multi-node.

  • fsdp — FullyShardedDataParallel via torchrun. Use when the model is too large for a single GPU. Supports multi-node.

Node and GPU counts are controlled by the SLURM allocation (sbatch --nodes, --gpus-per-node) or by the launcher CLI argument, not by the YAML config. The training config only selects the mode; the scheduler decides the resources.

FSDP-specific knobs (sharding strategy, mixed precision, CPU offload, etc.) live under distributed.fsdp.

Launch scripts

The unified launcher reads distributed.mode from the YAML:

# Auto-selects entrypoint based on distributed.mode
sbatch scripts/train.sh configs/my_config.yaml

# Multi-node (override nodes at submit time)
sbatch --nodes=2 scripts/train.sh configs/my_config.yaml

# Override GPUs per node
sbatch scripts/train.sh configs/my_config.yaml 2

Dedicated launchers are also available:

sbatch scripts/train_ddp.sh configs/my_config.yaml      # DDP
sbatch scripts/train_fsdp.sh configs/my_config.yaml     # FSDP

See Distributed Training Guide for FSDP-specific troubleshooting.
