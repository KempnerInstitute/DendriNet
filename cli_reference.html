Command-line reference

Installing the package installs the commands below ([project.scripts] in pyproject.toml). Each section reproduces the command’s --help output. The guides show how the commands fit together: Quickstart and Runs and outputs for training, Distributed training for several GPUs, Parameter sweeps for sweeps, Analyzing saved checkpoints for checkpoint analysis and the collectors, and Compact checkpoints for compact checkpoints.

Training

dendritic-train

Entry point: dendritic_modeling.scripts.training.train_experiments:cli_main

usage: dendritic-train [-h] [--output_dir OUTPUT_DIR] [--run_name RUN_NAME]
                       [--data_dir DATA_DIR]
                       [--learning_strategy {dfa,ei_equilibrium,fa,freeze_branch_kl,freeze_branches,freeze_layers,homeostatic_control,local_ca,multi_stage,presentation_stream,recurrent,soma_dfa,standard,voltage_stabilization}]
                       [--error_broadcast_mode {scalar,per_soma,per_soma_shared,per_soma_tree,per_soma_shuffled,local_mismatch,low_rank,path_transport,pathway_vector}]
                       [--seed SEED] [--epochs EPOCHS] [--lr LR] [--topk_lr TOPK_LR]
                       [--blocklinear_lr BLOCKLINEAR_LR]
                       [--reactivation_lr REACTIVATION_LR] [--decoder_lr DECODER_LR]
                       [--train_samples_per_class TRAIN_SAMPLES_PER_CLASS]
                       [--val_samples_per_class VAL_SAMPLES_PER_CLASS]
                       [--validate-only]
                       config

Run dendritic modeling training and evaluation.

positional arguments:
  config                Path to the configuration YAML file.

options:
  -h, --help            show this help message and exit
  --output_dir OUTPUT_DIR
                        Override output directory specified in config.
  --run_name RUN_NAME   Override run name specified in config.
  --data_dir DATA_DIR   Override data.base_dir (dataset root) specified in config.
  --learning_strategy {dfa,ei_equilibrium,fa,freeze_branch_kl,freeze_branches,freeze_layers,homeostatic_control,local_ca,multi_stage,presentation_stream,recurrent,soma_dfa,standard,voltage_stabilization}
                        Override learning strategy specified in config.
  --error_broadcast_mode {scalar,per_soma,per_soma_shared,per_soma_tree,per_soma_shuffled,local_mismatch,low_rank,path_transport,pathway_vector}
                        Override the LocalCA error-routing mode specified in config.
  --seed SEED           Override experiment seed (for running multiple seeds per
                        config).
  --epochs EPOCHS       Override the number of main-training epochs.
  --lr LR               Override the main trainer's fallback learning rate.
  --topk_lr TOPK_LR     Override the main trainer's sparse-synapse learning rate.
  --blocklinear_lr BLOCKLINEAR_LR
                        Override the main trainer's dendritic-coupling learning rate.
  --reactivation_lr REACTIVATION_LR
                        Override the main trainer's reactivation learning rate.
  --decoder_lr DECODER_LR
                        Override the main trainer's decoder learning rate.
  --train_samples_per_class TRAIN_SAMPLES_PER_CLASS
                        Bound ImageNet training samples per class (for a short check
                        run).
  --val_samples_per_class VAL_SAMPLES_PER_CLASS
                        Bound ImageNet evaluation samples per class (for a short check
                        run).
  --validate-only       Load and validate the config; build the datasets, model,
                        analysis manager, calibrated gates, optimizer and trainer;
                        write construction diagnostics, then exit without training.

Compact checkpoints

dendritic-compact-checkpoint

Entry point: dendritic_modeling.scripts.deployment.compact_checkpoint:main

usage: dendritic-compact-checkpoint [-h] [--compression-config COMPRESSION_CONFIG]
                                    [--verify-full-model] [--device DEVICE]
                                    [--report REPORT]
                                    experiment_config source_checkpoint
                                    output_checkpoint

Export a trained model with losslessly frozen sparse topology.

positional arguments:
  experiment_config     Training YAML used to construct the original model.
  source_checkpoint     File holding the model state dictionary, such as
                        final_model.pt.
  output_checkpoint     Compact checkpoint to write; it must not exist.

options:
  -h, --help            show this help message and exit
  --compression-config COMPRESSION_CONFIG
                        Standalone deployment-compression YAML.
  --verify-full-model   Compare deterministic full-model outputs before export and
                        after a fresh strict compact-checkpoint load.
  --device DEVICE       Device used for conversion and optional full-model
                        verification.
  --report REPORT       Atomically write the complete JSON resource and verification
                        ledger to this new file; an existing file is refused before
                        anything is written.

Sweeps

dendritic-sweep

Entry point: dendritic_modeling.scripts.sweeps.sweep_manager:main

usage: dendritic-sweep [-h] (--config CONFIG | --analyze)
                       [--generate-only | --run | --dry-run] [--split-jobs SPLIT_JOBS]
                       [--output-dir OUTPUT_DIR]
                       [--exclude-nodes EXCLUDE_NODES [EXCLUDE_NODES ...]]
                       [--slurm-account SLURM_ACCOUNT]
                       [--slurm-partition SLURM_PARTITION] [--results-dir RESULTS_DIR]

Unified Sweep Manager for Dendritic Modeling

options:
  -h, --help            show this help message and exit
  --config CONFIG       Path to sweep configuration file (for generation)
  --analyze             Analyze a finished sweep
  --generate-only       Generate configs only, don't submit jobs
  --run                 Generate configs and submit jobs (the default)
  --dry-run             Show what would be submitted without actually submitting
  --split-jobs SPLIT_JOBS
                        Run the configs as this many sequential jobs instead of one
                        array job
  --output-dir OUTPUT_DIR
                        Directory the sweep directory is created in (generation), or
                        the analysis output directory (--analyze)
  --exclude-nodes EXCLUDE_NODES [EXCLUDE_NODES ...]
                        List of nodes to exclude from job scheduling (e.g., --exclude-
                        nodes node1 node2)
  --slurm-account SLURM_ACCOUNT
                        Override slurm_config.account in sweep config (e.g.,
                        my_account)
  --slurm-partition SLURM_PARTITION
                        Override slurm_config.partition with one approved compute
                        partition
  --results-dir RESULTS_DIR
                        Sweep directory to analyze (with --analyze)

Examples:
  # Generate and run any sweep (default behavior)
  dendritic-sweep --config configs/my_sweep.yaml

  # Generate configs only (no job submission)
  dendritic-sweep --config configs/my_sweep.yaml --generate-only

  # Analyze a finished sweep
  dendritic-sweep --analyze --results-dir output/unified_sweep_20240101120000

  # Ten sequential jobs instead of one array job
  dendritic-sweep --config configs/my_sweep.yaml --split-jobs 10

  # Dry run (show what would be submitted)
  dendritic-sweep --config configs/my_sweep.yaml --dry-run

  # Override SLURM account/partition at submission time
  dendritic-sweep --config configs/my_sweep.yaml --slurm-account my_account --slurm-partition gpu_partition

dendritic-collect-sweep-metrics

Entry point: dendritic_modeling.scripts.sweeps.collect_sweep_metrics:main

usage: dendritic-collect-sweep-metrics [-h] --manifest MANIFEST
                                       [--output-dir OUTPUT_DIR]

Collect declared completed sweeps into checkpoint-level metric tables. This command is
the non-inferential boundary between standard sweep outputs and config-driven
checkpoint summaries. It uses the package ``DataCollector``, requires an explicit
expected size for every sweep, attaches only declared design labels, and records
hashes for all collected configs and held-out performance files. It never aggregates
across independently trained seeds.

options:
  -h, --help            show this help message and exit
  --manifest MANIFEST   Collection manifest (schema_version:
                        sweep_metric_collection_v1)
  --output-dir OUTPUT_DIR
                        Directory to write into (default: the manifest's output_dir)

Analysis

dendritic-analyze-checkpoint

Entry point: dendritic_modeling.scripts.analysis.run_checkpoint_analysis:cli_main

usage: dendritic-analyze-checkpoint [-h] --config CONFIG --checkpoint CHECKPOINT
                                    --analysis-config ANALYSIS_CONFIG --output-dir
                                    OUTPUT_DIR [--filename FILENAME] [--device DEVICE]
                                    [--no-strict]

Run config-declared analyses on one frozen model checkpoint. This entry point
reconstructs the model and canonical dataset splits from the original training config,
loads a frozen state dictionary, and executes a standalone analysis YAML through
:class:`~dendritic_modeling.analysis.AnalysisManager`. It never trains or modifies the
checkpoint.

options:
  -h, --help            show this help message and exit
  --config CONFIG       Resolved training YAML
  --checkpoint CHECKPOINT
                        Frozen model checkpoint
  --analysis-config ANALYSIS_CONFIG
                        Standalone YAML containing the analysis profile
  --output-dir OUTPUT_DIR
                        Directory the analyzers and the provenance record write into
  --filename FILENAME   Result name of the analyzers' output files
  --device DEVICE       For example cuda, cuda:0, cpu
  --no-strict           Allow missing or unexpected checkpoint keys and record them

dendritic-submit-checkpoint-analysis

Entry point: dendritic_modeling.scripts.analysis.submit_checkpoint_analysis:main

usage: dendritic-submit-checkpoint-analysis [-h] --manifest MANIFEST [--pilot]
                                            [--rerun] [--generate-only]
                                            [--account ACCOUNT]
                                            [--partition PARTITION]
                                            [--max-concurrent MAX_CONCURRENT]

Prepare and submit YAML-declared frozen-checkpoint analysis arrays. The manifest is
figure-agnostic: every scientific job is explicit, all inputs are hash-bound, complete
inventories are immutable, and retries receive new execution ledgers. This command
schedules only the standard package checkpoint analyzer; it does not train models or
compute paper-local quantities.

options:
  -h, --help            show this help message and exit
  --manifest MANIFEST   Checkpoint analysis manifest (checkpoint_analysis_manifest_v1)
  --pilot               Run only the manifest's pilot_job_ids
  --rerun               Also run jobs whose provenance and completion artifacts exist
  --generate-only       Write the job files and the submission record; submit nothing
  --account ACCOUNT     Slurm account (replaces the manifest's scheduler.account)
  --partition PARTITION
                        Slurm partition (replaces the manifest's scheduler.partition)
  --max-concurrent MAX_CONCURRENT
                        Array tasks running at once (a positive integer; default: the
                        manifest's scheduler.max_concurrent_jobs, else all pending
                        jobs)

dendritic-collect-checkpoint-analysis

Entry point: dendritic_modeling.scripts.analysis.collect_checkpoint_analysis:cli_main

usage: dendritic-collect-checkpoint-analysis [-h] [--config CONFIG] [--jobs JOBS]
                                             [--output-dir OUTPUT_DIR]
                                             [--require-analyzer REQUIRE_ANALYZER]
                                             [--expected-count EXPECTED_COUNT]
                                             [--metric-pattern METRIC_PATTERN]
                                             [--omit-full-results]
                                             [--derive-information-null-excess]
                                             [--input-hash-validation {recorded_hash_chain,rehash}]

Collect generic registered-analyzer outputs from frozen checkpoints. This collector is
deliberately schema-agnostic. It validates the checkpoint-run provenance, preserves
each complete result dictionary in JSONL, and emits a long table of finite numeric
leaves. It performs no across-checkpoint inference and never treats list elements,
branches, somas, or technical draws as replicates. Analyzers with dedicated technical-
draw collectors should continue to use them.

options:
  -h, --help            show this help message and exit
  --config CONFIG       Collection configuration file; replaces the other options
  --jobs JOBS           Job file (JSON Lines) of the analyzed checkpoints; repeat for
                        several files
  --output-dir OUTPUT_DIR
                        Directory to write the collected tables into
  --require-analyzer REQUIRE_ANALYZER
                        Analyzer whose results to collect; repeat for several
                        (default: every enabled analyzer)
  --expected-count EXPECTED_COUNT
                        Number of declared jobs the collection must contain
  --metric-pattern METRIC_PATTERN
                        Shell-style pattern of the dotted metric paths to keep, such
                        as '*accuracy*'; repeat for several (default: every numeric
                        value)
  --omit-full-results   Leave the complete result dictionaries out of the JSON Lines
                        file
  --derive-information-null-excess
                        Add the observed-minus-null value of every information term
                        that has a *_null counterpart
  --input-hash-validation {recorded_hash_chain,rehash}
                        rehash: hash the input files again; recorded_hash_chain:
                        compare the job file's *_sha256 values with the provenance

dendritic-collect-perturbation-response

Entry point: dendritic_modeling.scripts.analysis.collect_perturbation_response:cli_main

usage: dendritic-collect-perturbation-response [-h] --config CONFIG

Collect tidy accuracy responses from frozen-checkpoint perturbation analyses. The
registered noise and multiplicative-gain analyzers deliberately save their native
result dictionaries. This collector validates those outputs against an immutable
checkpoint-analysis ledger and aligns every perturbed accuracy with the clean accuracy
from the same checkpoint. It emits one row per checkpoint and perturbation level; it
performs no across-checkpoint aggregation.

options:
  -h, --help       show this help message and exit
  --config CONFIG  Collection configuration file

dendritic-collect-gain-load-response

Entry point: dendritic_modeling.scripts.analysis.collect_gain_load_response:cli_main

Collect frozen-checkpoint shared-gain/load factorial responses. The registered
analyzer emits one record per technical perturbation draw. This collector validates
immutable checkpoint provenance, verifies the complete factorial and common-random-

checkpoint-level tables. It performs no inference across independently trained
checkpoints.

options:
  -h, --help       show this help message and exit

dendritic-select-validation-epochs

Entry point: dendritic_modeling.scripts.analysis.select_validation_epochs:cli_main

usage: dendritic-select-validation-epochs [-h] --config CONFIG
                                          [--output-dir OUTPUT_DIR]

Select training epochs with validation metrics and report held-out metrics. The
command consumes the long-form trajectory emitted by ``dendritic-collect-sweep-
metrics``. Epochs are selected independently within each trained checkpoint using
validation metrics only. Metrics from the selected epoch, including held-out test
metrics when declared, are then exported for seed-level summarization. Test metrics

dendritic-poisson-exposure-transfer

Entry point: dendritic_modeling.scripts.analysis.run_poisson_exposure_transfer:cli_main

usage: dendritic-poisson-exposure-transfer [-h] --config CONFIG --checkpoint
                                           CHECKPOINT --transfer-config
                                           TRANSFER_CONFIG --output-dir OUTPUT_DIR
                                           [--device DEVICE] [--no-strict]

Evaluate one frozen Poisson-trained checkpoint across exposure durations. The command
reconstructs the model from its resolved training YAML, loads the checkpoint strictly,
rebuilds the canonical test split at each declared exposure, and delegates all
scientific evaluation to the package ``PoissonExposureTransferAnalyzer``. It never
retrains the model.

options:
  -h, --help            show this help message and exit
  --config CONFIG       Resolved training configuration of the run (its config.json)
  --checkpoint CHECKPOINT
                        Model checkpoint to evaluate
  --transfer-config TRANSFER_CONFIG
                        Transfer configuration file (durations, draws, seeds)
  --output-dir OUTPUT_DIR
                        Directory to write the results into
  --device DEVICE       For example cuda, cuda:0, cpu (default: cuda when available)
  --no-strict           Allow missing or unexpected checkpoint keys and record them
