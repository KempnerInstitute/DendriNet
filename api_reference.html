Python API

Most work with DendriNet goes through configuration files and the command-line programs (Command-line reference). This page documents the functions and classes for doing the same from Python: loading a configuration, building a model, adding components to the registries, running analyses and saving training state. The descriptions are taken from the docstrings in the source.

Configuration

dendritic_modeling.config.load_config(path: str | None = None, overrides: Mapping[str, Any] | None = None) → Config[source]

Load a configuration file, or return the validated defaults.

The file may extends a parent file (resolved relative to the file that names it). A sweep file is accepted as well; its base_config section is loaded. Every section is checked against the keys the library reads: unknown keys raise UnknownConfigKeyError, and keys retired from earlier library versions warn (see RETIRED_KEYS). Each call parses the file again, so edits are always picked up.

overrides maps dotted paths ("training.main.common.epochs") to values. They are applied to the composed file before validation, so an override is checked exactly like a value written in the file.

dendritic_modeling.config.config_from_mapping(data: Mapping[str, Any]) → Config[source]

Build and validate a Config from an in-memory mapping.

The mapping has the layout of a config file (experiment, data, model, …); it is checked exactly as load_config() checks a file.

dendritic_modeling.config.load_analysis_config(path: str, *, distributed_mode: str = 'none') → AnalysisConfig[source]

Load a standalone, typed analysis: YAML profile.

Checkpoint analyses often need to reuse an immutable training config while applying a newer measurement profile. Keeping the analysis profile in a separate YAML avoids copying or mutating the scientific training config. The input may either contain an analysis: root or be the analysis mapping itself.

class dendritic_modeling.networks.architectures.excitation_inhibition.dendritic.branch_dynamics.AdditiveRule(voltage: ~collections.abc.Callable[[...], ~typing.Any], options: ~collections.abc.Mapping[str, ~typing.Any] = <factory>, setup: ~collections.abc.Callable[[~typing.Any, dict[str, ~typing.Any]], None] | None = None)[source]

An additive integration rule that a plugin provides.

voltage(layer, *, excitation, inhibition, child_current, child_conductance, raw_voltage, inputs) returns the compartment voltage before reactivation. The currents are those of the built-in rules (raw_voltage is excitation - inhibition + child_current); inputs maps x, inhibitory_input and branch_input to the layer’s inputs on the feedforward path, and is None where voltages are computed from stored currents (recurrent and analysis paths), where a rule that needs the inputs must raise.

options holds the rule’s options and their defaults; a layer receives them as additive_options. setup(layer, options), if given, runs once while the layer is constructed (after its leak parameter) to create the rule’s parameters and buffers and to check the layer.

IndexedSparseLinear.effective_sparse_weight() → Tensor[source]

Return the [out_features, K] weights of the sparse projection.

These are the transformed weights after the optional row normalization, the values forward() multiplies the gathered inputs by (subclasses whose forward adds release noise or rounding apply those on top).

IndexedSparseLinear.project_with_weights(x: Tensor, weight: Tensor) → Tensor[source]

Project x through this layer’s contacts with other weights.

weight has the shape [out_features, K] of sparse_weight(); the result is out[..., i] = sum_j weight[i, j] * x[..., connection_indices[i, j]], computed with the layer’s projection backend. For example project_with_weights(x.abs(), effective_sparse_weight().abs()) sums the magnitudes of the synaptic drives. The layer’s state, including its resolved backend, is unchanged.

dendritic_modeling.networks.benchmarks.parameter_budget.match_parameter_budget(spec: dict, target_parameters: int, tolerance: float = 0.02) → tuple[dict, dict][source]

Find the nearest feasible integer width by counted monotone search.

All fields other than width remain fixed. A match is accepted only when the instantiated whole-model count differs from target by at most tolerance. Failure is explicit; neither extra inert weights nor an over-budget-only convention is used. Matching does not equalize compute or activation memory.

dendritic_modeling.networks.utils.readouts.make_signed_readout(input_dim: int, output_dim: int, *, rank: int | None = None, topk: int | None = None, bias: bool = False, init_std: float = 0.02, seed: int | None = None, projection_backend: str = 'eager') → Module[source]

Construct a signed readout with one explicit parameterization.

Omitting both budgets produces a dense map. rank chooses two dense factors, and topk chooses fixed indexed support. Indexed initialization follows the synapse initializer; its weights are not rescaled by init_std. An affine bias for indexed readouts must be applied by the caller.

dendritic_modeling.networks.architectures.excitation_inhibition.dendritic.passive_equilibrium.passive_star_soma_voltage(excitation: Tensor, membrane_conductance: Tensor, axial_conductance: Tensor, soma_leak: float = 1.0) → Tensor[source]

Solve independent passive stars, reducing the final branch dimension.

For branch current E, membrane load h and axial coupling g, the branch equilibrium is (E + g*s)/(h + g). The soma has leak to reversal zero and no direct input. Inputs broadcast; h and soma_leak must be positive and g nonnegative. Excitation is a current, not an extra conductance; callers construct h according to their model’s reversal potentials.

This positive-denominator expression avoids cancellation at large g. Its operation order is fixed, so results are reproducible bit for bit. It adds no model state, changes no layer defaults and performs no casts.

dendritic_modeling.deployment.compression.bitmask_slot_order_keys(model: Module, state_dict: Mapping[str, Tensor] | None = None) → set[str][source]

connection_indices keys whose contacts keep their slot order.

The bitmask encoding of a compact checkpoint may reorder a layer’s contacts into ascending input order only when that changes nothing but the order in which they are summed: the layer’s class itself (not only a parent class) declares SLOT_ORDER_MATTERS = False with pre_w as its only per-contact tensor (CONTACT_SLOT_STATE), and its state holds no other tensor with one entry per contact. Of the library’s layers only the fixed IndexedSparseLinear qualifies. Every other layer keeps its slot order (see compact_sparse_bitmask_state_dict()): indexed_release (per-contact impact and ages; release draws and cellwise rewiring follow slot positions), indexed_rewire (pruning ties, pairing of new inputs with pruned slots), indexed_dynamic (Top-K ties, selection noise) and layer types defined elsewhere.

dendritic_modeling.networks.checkpoints.compact_sparse_bitmask_state_dict(state_dict: Mapping[str, Tensor], *, keep_slot_order: bool | Collection[str] = False) → tuple[dict[str, Tensor], dict[str, str]][source]

Encode row-wise topology as bitmasks instead of integer indices.

This is useful for moderately dense topology, where even uint16 costs two index bytes per retained weight while a bitmask costs one bit per possible connection. Every connection_indices tensor with a pre_w of the same shape is encoded. A bitmask records which inputs a row contacts, not in which slot each contact is stored, so each key uses one of two layouts:

ascending (default; label "bitmask")

The contacts of each row and the matching pre_w entries are reordered into ascending input order, so the mask and the weights reconstruct the layer. This suits a layer whose only per-contact tensor is pre_w and whose training updates do not depend on the slot order, such as a fixed IndexedSparseLinear; its outputs can differ in the last bits because the contacts are summed in another order. A row that is not already ascending raises ValueError when the module holds another tensor with one entry per contact (indexed_release impact and ages, for example), which the reordering would misalign.

slot order (keys in keep_slot_order; label "bitmask_slot_order")

The contacts keep their slots and no other tensor changes. A key with a row that is not ascending also stores, under <key>.__bitmask_slot_order, the slot of each ascending contact (one byte per contact up to 256 contacts per row, two up to 65,536), and its metadata gains a fourth entry. Decoding restores the indices exactly. Library versions before 2026-10-13 cannot decode such keys and raise.

keep_slot_order is True (every key), False (none) or the connection_indices keys that keep their slot order.

dendritic_modeling.networks.checkpoints.decode_sparse_bitmask_state_dict(state_dict: Mapping[str, Tensor]) → dict[str, Tensor][source]

Restore row-wise indices from compact_sparse_bitmask_state_dict().

Keys in the ascending layout decode to ascending indices, aligned with the stored (reordered) pre_w; keys with a stored slot order decode to the indices in their original slots. Malformed or inconsistent entries raise RuntimeError.

Project provenance

Project provenance describes the source contract, export and evidence formats these functions read and the receipts they write.

dendritic_modeling.utils.project_source.read_contract(path: Path) → dict[str, Any][source]

Load the small, versioned source contract stored with a paper’s code.

library.line is core, llm or historical. A core or llm contract names library.maintained_ref, the full branch ref (refs/heads/... or refs/remotes/...) whose history must contain the pinned commit; a historical contract records an original source and names no maintained branch. library.release_bridge optionally names a source_commit and a release_commit for a release built by squashing (see verify_contract()). Raises SourceContractError for a malformed contract.

dendritic_modeling.utils.project_source.verify_contract(contract_path: Path, library_root: Path) → dict[str, Any][source]

Check exact source identity and cleanliness without running paper code.

The library checkout must be clean, its HEAD and library.ref must both be library.commit, and for a core or llm contract that commit must be library.maintained_ref or one of its ancestors. A release built by squashing has none of the source commits as ancestors; for it the contract declares library.release_bridge instead, and verification requires that the pinned commit is source_commit or one of its ancestors, that release_commit is the maintained ref or one of its ancestors, and that both commits have the same tree. The paper checkout must be clean and hold every declared source path and entry point.

Returns the receipt: contract, paper and library identities, the maintained ref and its commit, the verified bridge with its tree (only when one is declared), the package and configuration roots and the interpreter. Raises SourceContractError when a check fails.
