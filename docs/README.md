# DendriNet documentation sources

The `.rst` files in this directory are the Sphinx sources of the DendriNet
user documentation. `index.rst` holds the table of contents; every page is
listed there.

## Build

```bash
pip install -e ".[docs]"
python -m sphinx -b html -W --keep-going docs docs/_build/html
```

`-W` turns warnings into errors; keep the build warning-free. `cd docs && make
html` runs the same build without `-W`. Open `docs/_build/html/index.html` to
read the result. The Python API page (`api_reference.rst`) imports the package
from `src/` next to this directory, so the build needs the package's
dependencies installed.

## Generated pages

Two reference pages are written by scripts from the code. Do not edit them by
hand; rerun the script after changing what they describe, with the package
importable (`PYTHONPATH=src`), and commit the result:

| Page | Script | Source |
| --- | --- | --- |
| `cli_reference.rst` | `scripts/generate_cli_reference.py` | the `--help` output of the console scripts in `pyproject.toml` |
| `options_reference.rst` | `scripts/generate_options_reference.py` | the configuration dataclasses under `dendritic_modeling.config` |

Both scripts accept `--check`, which exits with status 1 when the page is out
of date.

## Checks

The example tests load every shipped YAML through its appropriate reader and
build the experiment models. The documentation tests check YAML excerpts
through the strict configuration loader, wrapping section fragments where
needed. Sweep-axis excerpts without a base configuration are explicitly
skipped; complete shipped sweeps are checked by the example tests. The
contextual-task examples have dedicated construction tests because their input
dimensions come from the dataset setup.

Run these checks from the repository root after changing an example:

```bash
PYTHONPATH=src python -m pytest \
  tests/test_all_example_configs_smoke.py tests/test_doc_yaml_snippets.py \
  tests/test_contextual_remapping_pipeline.py tests/test_population_target_levels.py
```

## Assets

- `_static/architecture/*.svg`: figures used by the pages, written by hand.
- `_static/dendritic_diagram.png`: the README schematic, generated by
  `scripts/generate_dendritic_diagram.py`.
- `_static/badges/coverage.svg` is the line coverage recorded in the README.
  The Python 3.11 CPU job measures it before the separate multi-process tests.
  The README uses a relative image path so private-repository readers can see it.

To refresh the badge, open a successful **CI Pipeline** run on `develop` and
download the `coverage-ubuntu-latest-3.11` artifact. It contains `coverage.xml`
and the `coverage.svg` generated from that report. Copy the SVG to
`docs/_static/badges/coverage.svg` and submit it in an ordinary pull request,
linking the CI run so reviewers can check the measurement.

Figures must not rely on colour alone: give each colour-coded element a label,
a line style or a marker shape as well.
