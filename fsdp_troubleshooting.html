Distributed Training Guide

Quick Start

Use the package entry points directly; wrap them in a site-local SLURM script when running on a cluster:

# DDP (data-parallel, model fits on one GPU)
torchrun --nproc_per_node=4 \
  -m dendritic_modeling.scripts.training.train_experiments \
  configs/my_config.yaml

# FSDP (model too large for one GPU)
python -m dendritic_modeling.scripts.training.train_experiments_fsdp \
  configs/my_config.yaml

When to Use What

Mode

When to use

none

Model fits on one GPU; single-process debugging

ddp

Model fits on one GPU; want data-parallel speedup across GPUs

fsdp

Model does NOT fit on one GPU; parameters must be sharded

Configuration

distributed:
  mode: fsdp             # none | ddp | fsdp
  fsdp:                  # FSDP-specific knobs (only used when mode=fsdp)
    sharding_strategy: "FULL_SHARD"  # FULL_SHARD, SHARD_GRAD_OP, NO_SHARD, HYBRID_SHARD
    mixed_precision: true
    cpu_offload: false
    min_num_params: 1000000
    sync_module_states: true
    use_orig_params: true
    backward_prefetch: "BACKWARD_PRE"
    gradient_checkpointing: false

Node and GPU counts are controlled by the SLURM allocation (--nodes, --gpus-per-node), not by the YAML config.

Common Issues

Network Timeout

Symptoms: NCCL timeout errors

Solutions:

  • The launch scripts set NCCL_SOCKET_IFNAME=ib0,eth0 for InfiniBand. If your cluster uses a different interface, override this in your script.

  • Use smaller batch sizes.

  • Check network connectivity between nodes.

Memory Issues

Symptoms: CUDA out of memory

Solutions:

  • Reduce training.main.common.batch_size.

  • Enable fsdp.gradient_checkpointing: true.

  • Use fsdp.cpu_offload: true (slow but saves GPU memory).

  • Use fsdp.sharding_strategy: FULL_SHARD (maximum sharding).

FSDP Validation

FSDP validation uses PaddedDistributedEvalSampler which pads each rank to equal batch counts (required by FSDP all-gather) but excludes padding samples from the metric reduction. This produces results numerically identical to a non-distributed validation run.

FSDP Final Analysis

After training, the FSDP script gathers the full (unsharded) state dict from all ranks, saves it as a checkpoint, then loads it into a plain non-FSDP model on rank 0 for analysis. This avoids running analysis on sharded parameters.

Autoencoder Pretraining

FSDP does not support autoencoder pretraining. If you need a pretrained encoder, train it separately with the standard single-GPU script, then point the config at the saved checkpoint.

Monitoring

squeue -u $USER
tail -f logs/train_fsdp_*.out
nvidia-smi
