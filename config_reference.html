Annotated reference configurations

Two complete configurations in configs/ carry a comment on every option: its type, the values it accepts and what it does. The values in the files are a working example, not the library defaults. Where a value differs from its default and the difference matters, the comment gives the default; an option that a file leaves out takes its default. Configuration guide explains how configs are loaded and checked and links the pages that document each option in full.

Single-process configuration

configs/config_exp.yaml trains a one-layer population network on CIFAR-10 in one process: an inhibitory population feeds an excitatory population whose neurons have a three-level dendritic tree. Besides the options this run uses, the file lists the options of the other training strategies, the local learning rules and most analyzers, so it can serve as a starting point. Check it without training:

dendritic-train configs/config_exp.yaml --validate-only

  2# SWEEP CONFIGURATION TEMPLATE
  3# ============================================================================
  4# Annotated template for parameter sweeps with DendriNet. docs/sweeps.rst
  5# describes every section, option and command.
  6#
  7# USAGE:
  8#   Generate the configs and job scripts without submitting (an empty account
  9#   or partition becomes PLACEHOLDER):
 10#     dendritic-sweep --config configs/sweep_config.yaml --generate-only
 11#
 12#   Generate the configs and submit the Slurm jobs (account and partition are
 13#   required, here or in slurm_config):
 14#     dendritic-sweep --config configs/sweep_config.yaml \
 15#       --slurm-account ACCOUNT --slurm-partition PARTITION

 17#   Train one generated config without Slurm:
 18#     dendritic-train <sweep_dir>/configs/unified_config_0.yaml

 20#   Tabulate and plot the finished runs (pass the sweep directory, not its
 21#   results/ subdirectory):
 22#     dendritic-analyze <sweep_dir>

 24# WHAT CAN BE SWEPT:
 25#   - Any option of base_config, through its dot path (sweep_config)
 26#   - E/I synapse-count pairs that satisfy a constraint (filter_config, A)
 27#   - Dendritic tree depths and branching patterns (filter_config, B)
 28#   - Named conditions that change several options together (sweep_variants)
 29#   All of these combine in one grid.

 31# HOW IT WORKS:
 32#   The sweep manager takes the Cartesian product of the sweep_config axes and
 33#   the sweep_variants, applies filter_config, and writes one training config

 39#   top-level key that nearly matches a section name. Other top-level keys are
 40#   reported in a warning and ignored; put annotations under metadata:.

 43#   slurm_config          - Slurm resources, environment and launcher
 44#   experiment_settings   - Replicate seeds (seeds_per_condition, base_seed, seed_paths)
 45#   sweep_config          - Axes: dot paths into base_config -> values or ranges

 49#   execution_results_dir - Optional separate root for the run outputs

209# ============================================================================
210# 4. FILTER CONFIG -- E/I Filtering and Branch Sweeps
211# ============================================================================
212# Two independent mechanisms that can be used alone or combined:
213#
214# A) E/I FILTERING -- keep only some excitatory/inhibitory synapse-count pairs
215# B) BRANCH SWEEP  -- add a dimension of dendritic trees to the grid
216#
217# --------------------------------------------------------------------------
218# A) E/I FILTERING
219# --------------------------------------------------------------------------
220# sweep_config must contain both E/I axes: the population_defaults
221# ff_excitatory_synapses and ff_inhibitory_synapses paths (population
222# networks) or model.core.connectivity.ee_synapses_per_branch_per_layer and
223# ie_synapses_per_branch_per_layer (structured E/I cores). The other axes are
224# crossed with the pairs that remain.
225#
226#   mode: "all"          - No filtering (the default; "default" is the same)
227#   mode: "ei-sum"       - Keep pairs with |E + I - value| <= tolerance
228#   mode: "ei-ratio"     - Keep pairs with I > 0 and |E / I - value| <= tolerance
229#   mode: "e-const"      - Keep E = value with every I (value must be on the E axis)
230#   mode: "i-const"      - Keep I = value with every E (value must be on the I axis)
231#   mode: "branch_sweep" - No filtering; required for a branch sweep without
232#                          sweep_config axes or sweep_variants
233#
234#   value: <number>      - Target value; required by the four E/I modes
235#   tolerance: <number>  - Required by ei-sum and ei-ratio (0 = exact match)
236#   A filter that keeps no pair raises.
237#
238# EXAMPLES (with E and I axes of [10, 20, 30, 40] each):
239#   # Keep the pairs with E + I = 50 (4 pairs):
240#   # mode: "ei-sum"

244#   # Keep the E/I ratios within 0.5 of 2.0 (3 pairs):
245#   # mode: "ei-ratio"
246#   # value: 2.0
247#   # tolerance: 0.5

249#   # Hold inhibition at 10 (4 pairs):
250#   # mode: "i-const"
251#   # value: 10

253# --------------------------------------------------------------------------
254# B) BRANCH SWEEP
255# --------------------------------------------------------------------------
256# Each generated tree replaces branch_factors of every excitatory population
257# (polarity "excitatory" or no polarity) in every population_network layer
258# (model.core.architecture.excitatory_branch_factors for structured E/I
259# cores). Remove any sweep_config axis on those branch_factors first: the tree
260# overwrites it, and conditions that differ only in that axis become
261# identical runs. A factor b at depth d gives d levels of b branches. Depths
262# and factors are axis values: literal lists or explicit ranges (section 3).
263#
264# branch_sweep_mode options:
265#
266#   "uniform_sweep"   - Every depth with every branch factor (default mode)
267#     dendrite_tree_depth: {range: {start: 1, stop: 4, step: 1}}
268#     dendrite_branches_per_layer: {values: [2, 3]}
269#     Example: depths 1-4 x factors 2, 3 -> 8 trees ([2], [3], [2, 2], ...)
270#
271#   "depth_sweep"     - Vary the depth with one branch factor at every level
272#     dendrite_tree_depth: {range: {start: 2, stop: 5, step: 1}}
273#     uniform_branches_per_layer: 4
274#     Example: [4, 4], [4, 4, 4], [4, 4, 4, 4], [4, 4, 4, 4, 4] -> 4 trees
275#
276#   "width_sweep"     - Vary the branch factor at a fixed depth
277#     fixed_dendrite_tree_depth: 3
278#     dendrite_branches_per_layer: {range: {start: 2, stop: 8, step: 2}}
279#     Example: [2, 2, 2], [4, 4, 4], [6, 6, 6], [8, 8, 8] -> 4 trees
280#
281#   "pattern_sweep"   - Named branching patterns across depths
282#     dendrite_tree_depth: {range: {start: 2, stop: 4, step: 1}}
