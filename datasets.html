Datasets

data.dataset_name selects the dataset of a run (default cifar10). data.processing holds the input options shared by all datasets, and data.dataset_params.<dataset_name> holds the options of the selected dataset. experiment.train_valid_split and the experiment test-split options decide how the data are divided.

experiment:
  train_valid_split: 0.8
data:
  dataset_name: mnist
  base_dir: ""            # empty: DENDRITIC_DATA_DIR or the user cache
  processing:
    flatten: true
    normalize: false
  dataset_params: {}

Selecting a dataset

An unknown data.dataset_name raises when the datasets are built, with the closest known name and the full list of names. The Dataset catalogue below lists every name the loaders accept.

data.dataset_params maps dataset names to option blocks. Only the block named by data.dataset_name is read; blocks for other datasets are ignored, so one file can keep the options of several datasets. A key in the selected block that its loader does not read raises, with a close match when there is one. These keys are checked when the dataset is built (at the start of training, or with dendritic-train config.yaml --validate-only), not when the configuration file loads. Annotations for people or other tools belong in the top-level metadata: section.

A flatten or normalize key in the selected dataset_params block takes precedence over data.processing. Generated datasets draw their samples from experiment.dataset_seed unless the block sets seed, and random train/validation partitions use experiment.split_seed; both fall back to experiment.seed (see Random seeds and reproducibility flags).

Training, validation and test splits

Every loader returns three splits. The test split is the dataset’s own test set: the MNIST and CIFAR test sets, the official ImageNet validation set, or a separately generated test set.

Training and validation

experiment.train_valid_split (default 0.8) is the fraction of the training data kept for training; the rest forms the validation split, which selects the best checkpoint (training.main.common.load_best_state_dict) and drives early stopping. The partition is random, seeded by experiment.split_seed. It applies to:

  • the vision, paired arithmetic, Poisson and ImageNet datasets (the paired datasets split their base images before pairing them);

  • sequence datasets that generate one training set and one test set, which is every sequence dataset without explicit splits (below). The counterfactually paired datasets (contextual_ready_set_go and bayesian_ready_set_go) keep both members of a pair in the same split;

  • stringer_v1, whose fixed test split is 10% of the trials.

It does not apply to:

  • the synthetic datasets. The first ten split one generated set 60/20/20 into training, validation and test; contextual_stream_gain_shift, branch_local_gain_load and hierarchical_gain_load generate each split separately (see Synthetic datasets);

  • sequence datasets with explicit splits;

  • registered datasets such as contextual_remapping, which define their own splits.

The value must lie in [0, 1]; other values raise when the configuration loads, and 0 raises when the datasets are built for every dataset except registered ones. At 1.0 the datasets above have an empty validation split. A run then stops during setup when training.main.common.load_best_state_dict or early_stopping is true (both are by default), because both select on the validation loss; with both false, the validation loss is recorded as NaN.

Explicit splits for sequence tasks

Several sequence builders accept train, valid and test mappings inside their dataset_params block. Each mapping overrides task parameters for one split, and experiment.train_valid_split is then not used. This is how a test split can use delays that the training split never sees:

data:
  dataset_name: timescale_generalization
  dataset_params:
    timescale_generalization:
      n_samples: 20000
      train: {min_delay: 10, max_delay: 50}
      valid: {min_delay: 10, max_delay: 50}
      test: {min_delay: 60, max_delay: 100}

A split without a mapping uses the common values. n_samples in a mapping sets the size of that split; by default the training split has n_samples examples and the validation and test splits have max(n_samples // 5, 2000).

Sealed test split

These experiment options protect the test split of a confirmatory run:

max_test_samples (default null)

Upper bound on the size of the built test split. A larger test split raises; nothing is subsampled. It applies whenever it is set.

sealed_test (default false)

Seals the test split. It requires allow_test_data: false and max_test_samples, and training then refuses to start while any analysis is enabled, since analyzers read the test split.

allow_test_data (default true)

false is part of the seal and is accepted only with sealed_test: true.

record_dataset_fingerprints (default false)

Writes dataset_fingerprints.json to the run directory: content hashes (SHA-256) of the tensors and stored attributes of the training, validation and test datasets, and one combined hash. For file-backed datasets such as ImageNet the hash covers the stored file list, not the image bytes.

A sealed run on a generated dataset whose test split has 400 examples:

experiment:
  sealed_test: true
  allow_test_data: false
  max_test_samples: 400
  record_dataset_fingerprints: true
data:
  dataset_name: correlated_gaussian
  dataset_params:
    correlated_gaussian:
      n_samples: 1000

The check that rejects enabled analyses is part of training: dendritic-analyze-checkpoint runs the analyses it is given on a saved checkpoint even when its training configuration seals the test split (see Analyzing saved checkpoints).

Where data are stored

The data root is data.base_dir when it is set; otherwise $DENDRITIC_DATA_DIR; otherwise $XDG_CACHE_HOME/dendritic_modeling (~/.cache/dendritic_modeling when XDG_CACHE_HOME is unset), so runs share one copy. dendritic-train --data_dir <path> overrides data.base_dir. Each run logs the data root and records DENDRITIC_DATA_DIR in runtime_environment.json.

Torchvision datasets are downloaded on first use into subdirectories of the root:

  • <root>/datasets/mnist: MNIST, also used by sequential_mnist, the MNIST paired datasets and the Poisson generator on MNIST;

  • <root>/datasets/fashion_mnist: Fashion-MNIST;

  • <root>/datasets/cifar: CIFAR-10 and CIFAR-100, also used by the CIFAR-10 paired datasets and the Poisson generator on CIFAR-10.

Processes that load the same directory at once take turns through a .download.lock file in it. A missing or corrupted copy is deleted and downloaded again.

Three datasets read local files and never download by default: ImageNet (see ImageNet), stringer_v1 (see Neural recordings: stringer_v1) and contextual_remapping, which downloads EMNIST only with download: true (see Registered datasets).

Input processing

data.processing has three options. A written true that the selected loader cannot apply raises instead of being ignored.

flatten (default: unset, which loaders treat as true)

Return inputs as vectors. Vision, paired and Poisson datasets flatten when it is unset; ImageNet then raises, so ImageNet runs set flatten: false. Synthetic datasets are already flat and accept true. Sequence and registered datasets keep their own layout and raise on true.

normalize (default: unset, which loaders treat as false)

Dataset-specific input scaling. For the vision, paired and ImageNet datasets, true subtracts the per-channel mean and divides by the standard deviation (torchvision Normalize with the dataset’s statistics). sequential_mnist divides pixel values by 255 and stringer_v1 z-scores every neuron, both unless normalize: false. The synthetic, Poisson, other sequence and contextual_remapping datasets have no input scaling and raise on true.

label_noise_rate (float in [0, 1], default 0.0)

Fraction of training labels replaced by a class drawn uniformly from all classes, including the original one, so about label_noise_rate * (C - 1) / C of the labels change for C classes. Only the training split changes. The draws use experiment.dataset_seed. Only mnist, fashion_mnist, cifar10 and cifar100 apply it; a positive rate for any other dataset raises.

data:
  dataset_name: cifar10
  processing:
    flatten: true
    normalize: true
    label_noise_rate: 0.2

Shunting models with positive weight transforms expect non-negative input to their first shunting layer. normalize: true makes the inputs signed: keep normalize: false, or rectify the transfer layer of a structured E/I core with model.core.transfer.output_activation set to relu, softplus or sigmoid.

Vision datasets

mnist, fashion_mnist, cifar10 and cifar100 load the torchvision datasets into memory as tensors with values in [0, 1] (before normalize). With the default flatten the inputs are vectors of 784 (MNIST, Fashion-MNIST) or 3072 (CIFAR) values; with flatten: false they keep the [channels, height, width] shape. They read no dataset_params keys.

Paired arithmetic datasets

Each split is built from the matching split of the base dataset: the images are permuted and the first half is paired with the second half, so one pass gives n // 2 pairs. shuffle_iterations repeats the pairing with further permutations and multiplies the split size accordingly.

mnist_modulo10

Concatenates the two images along the last axis (a 1568-value vector by default) and labels the pair (a + b) mod 10. Options: shuffle_iterations: 2, pair_seed: 0.

cifar10_modulo10

Labels a pair of CIFAR-10 images (a + b) mod 10. With the default flatten the input is the two flattened images; with flatten: false the images sit side by side. Options: shuffle_iterations: 1, pair_seed: 0.

double_mnist_contextual_mod10, double_cifar10_contextual_mod10

Draw a random context for every pair (seeded by context_seed). Context 0 labels the pair (a + b) mod 10 and context 1 (a - b) mod 10. The context is appended as a two-value one-hot vector, or as two constant image planes with flatten: false. Options: shuffle_iterations: 1, pair_seed: 0, context_seed: 123.

data:
  dataset_name: double_mnist_contextual_mod10
  dataset_params:
    double_mnist_contextual_mod10:
      shuffle_iterations: 2
      pair_seed: 0
      context_seed: 123

Poisson generator

poisson_generator treats the pixel intensities of a base dataset as rates. Every access draws fresh noise, so each epoch and each evaluation sees different samples:

\[\tilde{x} = \mathrm{Poisson}(T\, g\, x) / T,\]

where T = stimulus_duration and g is the gain. Options of data.dataset_params.poisson_generator:

base_dataset (default mnist)

mnist or cifar10. Any other name raises. The base images are not normalized.

poisson_sampling (default true)

false returns g x without noise.

stimulus_duration (default 1.0)

T: longer stimuli give more counts and relatively less noise.

multiplicative_gain (default true)

Apply the gain g. With false the gain options are not used.

fixed_gain_factor (default null)

One gain for every input. It takes precedence over the bounds below.

max_gain_factor (default null)

Draw g from [1, max_gain_factor]; it must be at least 1.

max_gain_tau_ratio (default null)

Sets the upper bound to max_gain_tau_ratio * stimulus_duration when max_gain_factor is not set.

gain_sampling (default log_uniform)

log_uniform draws log g uniformly; linear_uniform draws g uniformly.

uniform_gain (default true)

true draws one gain per sample; false draws one gain per input element and needs a fixed gain or an upper bound.

With the defaults no bound is set and the gain is 1, so only Poisson noise is added. Of the processing options only flatten applies; normalize: true and label noise raise.

data:
  dataset_name: poisson_generator
  dataset_params:
    poisson_generator:
      base_dataset: mnist
      max_gain_factor: 10.0
      stimulus_duration: 1.0

Synthetic datasets

Synthetic datasets are generated in memory from experiment.dataset_seed (or the block’s seed). Their inputs are flat vectors.

  • The first ten datasets below generate n_samples examples per class, with inputs in [0, 1], shuffle them and split the set 60/20/20 into training, validation and test. nonlinear_interaction, nonlinear_separable and population_code assign classes after sampling and drop examples of the larger class to balance them, so their total can be smaller than n_samples times the number of classes. Inputs combine ne excitatory-designated and ni inhibitory-designated features, and input_dim must equal ne + ni where both appear.

  • contextual_stream_gain_shift, branch_local_gain_load and hierarchical_gain_load generate the training, validation and test splits separately, with about n_samples examples each. Their test split is drawn from a shifted gain distribution, and so is their validation split unless valid_split_mode: train: checkpoint selection and early stopping then see test-distribution data. Leaving valid_split_mode unset logs a warning; set it explicitly.

Sequence datasets

Sequence datasets return inputs of shape [time, features] for recurrent cores (a recurrent population_network or one of the recurrent cores in Core types). The target is a class label, a per-step label sequence, a distribution over time steps, or a regression target, as listed per dataset. Tasks with variable trial lengths also return each trial’s length. Regression tasks (adding_problem, lorenz, lorenz_sequence, multi_sine_forecast, switching_lds) need model.task: regression.

Shared conventions:

  • Sizes. n_samples is the size of the training data before the validation split. The test split has max(n_samples // 5, minimum) examples, with a minimum of 1000 for copy_task, adding_problem, variable_delay_dms and the signal tasks and 2000 for the others. sequential_mnist and stringer_v1 use the recorded data instead.

  • Seeds. seed defaults to experiment.dataset_seed. Tasks that build their test split from a second seed default it to seed + 1 (test_seed where listed).

  • Positive encoding. A _positive name selects inputs that are never negative, for shunting models with positive conductances. Setting positive_input_encoding: true under the base name selects the same encoding.

  • Processing. flatten and normalize raise when true (except normalize for sequential_mnist and stringer_v1), and label noise raises.

data:
  dataset_name: context_dependent_decision
  dataset_params:
    context_dependent_decision:
      n_samples: 20000
      signal_dim: 8
      noise_std: 1.0
      variable_integration: true
      min_integration: 20
      max_integration: 80

Interval timing tasks

In the Ready-Set-Go tasks a Ready pulse and a Set pulse are separated by a sampled interval, and the model reproduces the interval after Set. The target is the Go time, for training.main.common.loss_function: temporal_event_ce: a normalized distribution over the time steps (ready_set_go, contextual_ready_set_go, bayesian_ready_set_go) or one Go step (factual_bayesian_ready_set_go). The sequence length is fixed for all trials; when sequence_duration is unset it is the shortest length that fits every trial. set_min_step and set_max_step bound the Set time and default to values derived from the intervals.

Neural recordings: stringer_v1

stringer_v1 classifies the orientation of drifting gratings from mouse V1 population responses (Stringer et al., 2019, Science 364). Each example is a static vector of n_neurons responses, not a sequence, so it suits feedforward cores. The data are not downloaded: data_dir (default: the data root) must contain the response file grating_file (default gratings_drifting_GT3_2019_04_05_1.npy) and all_running.npy; session_id selects another session by name and then also needs database.npy.

n_neurons (default 500)

Number of neurons kept, ranked by response variance.

n_classes (default 8)

Number of orientation bins over [0, 2*pi).

normalize (default true)

Z-score every neuron.

neuron_selection_scope (default all_trials)

all_trials ranks neurons on all trials (transductive); train_split ranks them on the training trials only and reuses that ranking for the test trials.

The test split is a fixed 10% of the trials drawn with the dataset seed, and the validation split comes from the remaining trials through experiment.train_valid_split. The block also accepts running-state options (running_state, running_quantile, train_running_state, test_running_state, state_holdout_fraction, running_residualize, running_residualize_clip), gain augmentation (gain_group_count, gain_grouping, global_gain_min/max, group_gain_min/max, gain_seed) and Poisson resampling (poisson_sampling, poisson_rate_scale). The gain, Poisson and residualization options also take train_ and test_ prefixes to differ between the training and test trials. Setting train_running_state and test_running_state to disjoint states (low and high) trains on one running state and tests on the other; see StringerV1Dataset in dendritic_modeling.datasets.sequence.neuro_tasks.

Registered datasets

contextual_remapping

The context-cued EMNIST Balanced task (47 classes). Each presentation shows an image with a random context c of num_contexts; the label is (label + c) mod 47 and the context is appended as a one-hot cue scaled by context_scale. The image (not the cue) is corrupted by a log-uniform gain in [gain_min, gain_max] and brightness-dependent Gaussian noise whose divisor is log-uniform in [noise_divisor_min, noise_divisor_max].

It requires training.main.strategy: presentation_stream: the training split serves freshly corrupted presentations, and indexing it returns clean context-0 items that only fix the input shape. It defines its own splits: pool_per_class training images per class are held out, the first validation_per_class of them form a fixed corrupted validation set, and the test split is the corrupted official EMNIST test set. EMNIST is read from <root>/raw (root defaults to the data root) and downloaded there only with download: true. Processing options raise.

Options and defaults: root: "", download: false, upright: true, peak_normalize: true, pool_per_class: 200, validation_per_class: 50, partition_seed: 31003, num_contexts: 32, context_scale: 1.0, gain_min: 0.05, gain_max: 20.0, noise_divisor_min: 1.0, noise_divisor_max: 4.0, validation_seed: 78019, test_seed: 99173, generator_device: cpu (cuda draws the evaluation corruptions on a GPU). Unknown keys raise.

Adding a dataset

dendritic_modeling.datasets.registry.register_dataset(name, builder, ...) adds a dataset selectable by data.dataset_name. The builder receives the task configuration (attributes dataset, data_path, train_valid_split and parameters, the merged processing options, dataset parameters and seeds) and returns (train, valid, test). Keyword options declare a required_strategy and the processing options the builder applies (others then raise). Registered names are looked up before the built-in loaders, so register a name that no built-in dataset uses. dendritic_modeling.datasets.sequence.register_sequence_dataset_builder adds a sequence builder that the shared sequence factory splits. See Extension registries.

ImageNet

imagenet loads ILSVRC-2012 from a local copy; it is never downloaded, and a missing copy raises with the resolved paths (there is no synthetic fallback). Point data.base_dir at the ImageNet root:

data:
  dataset_name: imagenet
  base_dir: "/path/to/imagenet"
  processing:
    flatten: false
    normalize: true
  dataset_params:
    imagenet:
      transform_preset: pretrained
      loader_backend: auto

Two layouts are recognized in the data root, and otherwise in <root>/datasets/imagenet:

  • a torchvision ImageNet root: the devkit (meta.bin, ILSVRC2012_devkit_t12.tar.gz or ILSVRC2012_devkit_t12/) with training (train/ or ILSVRC2012_img_train/) and validation (val/ or ILSVRC2012_img_val/) images;

  • class directories: train/<class>/ (or ILSVRC2012_img_train/<class>/) and val/<class>/, loaded with torchvision ImageFolder.

Options of data.dataset_params.imagenet:

loader_backend (default auto)

auto uses a torchvision root when one is found and class directories otherwise; torchvision forces torchvision.datasets.ImageNet; imagefolder forces class directories and skips the devkit metadata.

transform_preset (default legacy_resize)

legacy_resize resizes every image to 224x224. pretrained uses RandomResizedCrop(224) and horizontal flips for training and Resize(256) then CenterCrop(224) for evaluation; use it for torchvision pretrained backbones.

train_samples_per_class, val_samples_per_class (default null)

Keep a seeded random subset of at most this many images per class. train_samples_per_class limits the training images before the validation split is drawn from them; val_samples_per_class limits the test split. dendritic-train --train_samples_per_class N --val_samples_per_class M sets them from the command line for short test runs.

allow_flatten_materialize (default false)

ImageNet requires processing.flatten: false; an unset flatten counts as true and raises. allow_flatten_materialize: true instead materializes flattened tensors in memory, keeping at most the first 50,000 examples of each split. It is meant for debugging only.

The validation split is the random 1 - train_valid_split fraction of the training images, seeded by experiment.split_seed and loaded with the evaluation transform. The test split is the official validation set. normalize: true applies the ImageNet channel mean and standard deviation.

Two environment variables help with large copies on shared filesystems:

IMAGENET_LOCAL_DIR

When it names an existing directory, ImageNet is loaded from there instead of the data root, for example from a copy on local disk.

DENDRITIC_IMAGEFOLDER_CACHE

A directory for a cached ImageFolder index (class names and file list). The first run scans the class directories and writes the index; later runs read it instead of scanning about 1.28 million files.

ImageNet protocol loaders

dendritic_modeling.datasets.imagenet_protocol builds single ImageNet splits of a run without loading the others, for example to evaluate another model on exactly the images a run trained, selected and tested on. Both functions take the run’s configuration (as returned by dendritic_modeling.config.load_config), require data.dataset_name: imagenet and processing.flatten: false, and read the ImageNet location, loader_backend, transform_preset and normalize from it. They find the data where training does: data.base_dir, else $DENDRITIC_DATA_DIR, else the cache directory.

build_protocol_train_partition(config)

Returns (train, valid, info): the training subset with the training transform and the disjoint validation subset with the evaluation transform, partitioned exactly as in training (train_valid_split and experiment.split_seed, which falls back to experiment.seed). It raises when train_samples_per_class is set.

build_protocol_test_dataset(config)

Returns (test, info): the official validation set with the evaluation transform. It raises when val_samples_per_class is set.

info records the ImageNet directory, backend, transform preset and transforms, normalize, and the split sizes (and, for the training partition, train_valid_split and the split seed).

Loading during training

The DataLoader settings of training are fields of training.main.common (num_workers, pin_memory, persistent_workers, prefetch_factor, in_order), listed under “Training loop options” in Training; analyses use analysis.runtime instead (see Data iteration: analysis.runtime). Except under FSDP, training records the resolved settings under dataloader_tuning in training_summary.json. Left unset, they depend on the dataset type:

  • In-memory TensorDataset data (the vision and synthetic datasets, also inside Subset or ConcatDataset) load in the main process.

  • Other datasets, including the package’s generated sequence datasets, the Poisson generator and the paired datasets other than mnist_modulo10, use worker processes. Set num_workers: 0 to load them in the main process. From the second epoch on, the shuffle order and the per-sample random draws differ between main-process, persistent-worker and non-persistent-worker loading, so keep these settings fixed when runs must match.

  • ImageNet and other torchvision image-folder datasets use workers with prefetch_factor: 4 and in_order: false.
