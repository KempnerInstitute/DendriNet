Population networks

A population network (model.core.type: population_network) builds the model core from ordered layers of named dendritic populations that are joined by explicit, directed connections. The same notation describes a single feedforward E/I layer, several cell classes with their own morphologies, multilayer routing and recurrent microcircuits. This page covers the schema, the connection rules, every population option and the timing controls. Receptor kinetics, spiking somata, dendritic spikes and soma-to-dendrite feedback are described in Temporal dynamics.

Layers, populations and connections

A population-network core reads only model.core.population_network, apart from model.core.type, model.core.initialization_seed and model.core.biological_neuron (see Biological constraints). Any other model.core section written with a non-default value, for example model.core.morphology or model.core.sparsity, raises when the configuration loads; the corresponding settings are population options (see Options reference). The network has four kinds of parts:

layers[]

Layers run in order. Each layer contains populations and the connections into them, and outputs the activity of its readout population.

layers[].populations[]

Named groups of dendritic neurons. Each population has a polarity (excitatory or inhibitory), a number of neurons and a dendritic morphology (branch_factors, see The dendritic tree).

layers[].connections[]

Directed records from a source (the network input, a population of the same layer or a population of another layer) to a population of the layer, read either in the same timestep or from the previous timestep.

layers[].population_defaults and layers[].populations[].population

Population options: synapse counts, integration rule, reactivation gates, sparse synapse type, time constants and temporal dynamics.

The feedforward E/I layer consists of one inhibitory and one excitatory population. The input drives both, and the inhibitory population inhibits the excitatory one:

model:
  core:
    type: population_network
    population_network:
      layers:
        - name: layer0
          readout_population: e
          population_defaults:
            ff_excitatory_synapses: 8
            ff_inhibitory_synapses: 4
          populations:
            - {name: i, polarity: inhibitory, n_neurons: 32, branch_factors: [1]}
            - {name: e, polarity: excitatory, n_neurons: 128, branch_factors: [4, 4]}
          connections:
            - {source: input, target: i}
            - {source: input, target: e}
            - {source: i, target: e}

How a layer computes

Each population has up to four input streams: the same-step streams ff_excitatory and ff_inhibitory, and the delayed (previous-timestep) streams rec_excitatory and rec_inhibitory. A connection adds its source to one stream of its target: the network input and excitatory populations enter an excitatory stream, inhibitory populations an inhibitory stream. The sources of a stream are concatenated, and every dendritic compartment of the target selects a fixed number of synapses from them, set by ff_excitatory_synapses, ff_inhibitory_synapses, rec_excitatory_synapses and rec_inhibitory_synapses. The sparse synapse type (topk_type, see Sparse synapse types) decides how the synapses are chosen; connection masks decide which source units are eligible.

The populations of a layer run in the order of their same-step connections, sources before targets. The output of a layer is the output of its readout population (readout_population, by default the first excitatory population), and the next layer receives it as input. The network output is the readout population of the readout layer (readout_layer, by default the last layer), which feeds the decoder.

When the configuration loads, the structure of the network is checked: every layer needs an excitatory population, every population needs at least one enabled same-step connection into its ff_excitatory stream, names must be unique (population names within their layer) and must not contain a dot, and connection sources, targets, timing, pathways and probabilities must be valid. The keys and values of layers, populations, connections and population options are checked when the model is built, so a misspelled key there fails only at build time. dendritic-train config.yaml --validate-only builds the model, datasets and trainer without training and reports these errors early (see How configs are checked).

External input streams

The first layer reads the network input through three source names:

  • Without a transfer layer (use_transfer: false, the default) input, input_e and input_i are the same tensor. input and input_e enter the target’s excitatory stream and input_i its inhibitory stream, so a population that reads input and input_i receives every input channel as both excitation and inhibition.

  • With use_transfer: true the transfer layer turns the input into an excitatory and an inhibitory stream (see TransferLayer). input_e is the excitatory stream and input_i the inhibitory stream; input is the same as input_e.

input_exc and input_excitatory are accepted for input_e, and input_inh and input_inhibitory for input_i. input_e and input_i reach only the first layer, and naming them in a later layer raises. In a later layer, input is the readout population of the previous layer, and its synapses take that population’s polarity: an inhibitory readout population drives ff_inhibitory synapses. External sources cannot use timing: delayed.

This first layer reads independent excitatory and inhibitory halves of a 784-dimensional input:

model:
  core:
    type: population_network
    population_network:
      use_transfer: true
      transfer_params:
        independent_pathways: true
        excitatory_dim: 392
        inhibitory_dim: 392
      layers:
        - name: layer0
          readout_population: e
          populations:
            - {name: i, polarity: inhibitory, n_neurons: 32, branch_factors: [1]}
            - {name: e, polarity: excitatory, n_neurons: 128, branch_factors: [4, 4]}
          connections:
            - {source: input_e, target: i}
            - {source: input_e, target: e}
            - {source: input_i, target: e}
            - {source: i, target: e}

The input passes through three optional stages before it reaches the first layer, in this order:

  1. input_transform adapts the encoder output: identity (default), relu, or signed_split, which writes the positive and negative parts of each feature as separate non-negative channels and doubles the input width.

  2. The transfer layer (use_transfer and transfer_params).

  3. input_projection_dims adds linear layers, each followed by a ReLU. With a transfer layer they project input and input_e only; input_i keeps the width produced by the transfer layer.

Shunting populations with a positive weight transform treat their input as non-negative rates. When the first batch shows signed input reaching such a first-layer population (for example images normalized with data.processing.normalize: true), the network logs a warning once. Use input_transform: relu or signed_split, a transfer layer with a non-negative output_activation, input_projection_dims, or non-normalized data.

Cross-layer sources

A source of the form layer_name.population_name (a qualified source) reads a population of another layer. Same-step qualified sources must come from earlier layers. Delayed qualified sources may come from any other layer, including later layers, and read that population’s previous-timestep output; the target layer must set recurrent: true. A qualified source that names its own layer raises; use the plain population name instead.

In this excerpt of model.core.population_network, the second layer reads both populations of the first layer instead of only its readout population:

layers:
  - name: layer0
    readout_population: e0
    populations:
      - {name: i0, polarity: inhibitory, n_neurons: 32, branch_factors: [1]}
      - {name: e0, polarity: excitatory, n_neurons: 128, branch_factors: [3, 3, 3]}
    connections:
      - {source: input, target: i0}
      - {source: input, target: e0}
  - name: layer1
    readout_population: e1
    populations:
      - {name: i1, polarity: inhibitory, n_neurons: 16, branch_factors: [1]}
      - {name: e1, polarity: excitatory, n_neurons: 64, branch_factors: [3, 3, 3]}
    connections:
      - {source: layer0.e0, target: i1}
      - {source: layer0.e0, target: e1}
      - {source: layer0.i0, target: e1}
      - {source: i1, target: e1}

Timing

Same-step connections between populations of a layer must form a directed acyclic graph; a cycle such as i -> e together with e -> i raises when the configuration loads. Delayed connections (timing: delayed) read the source’s output from the previous timestep, so they may form cycles, including a population connected to itself. They require recurrent: true on the layer, and at the first timestep they read zeros. Mutual E/I interaction is therefore written as one same-step direction and one delayed direction, or as two delayed connections.

Pathways and synapse counts

The pathway of a connection is the input stream it feeds. It follows the polarity of the source unless written explicitly, and it must match the timing. Each compartment of the target selects <pathway>_synapses contacts (or the per-level <pathway>_synapses_by_level) from the eligible units of all sources of that stream. When a mask leaves a compartment fewer eligible units than this count, the Top-K selection types (standard, stochastic, variance, dense_to_sparse) use only the eligible ones, and the indexed types raise.

Every enabled connection must be able to reach a synapse: its pathway needs a positive count at a depth the connection targets, where the soma counts only with somatic_synapses: true. The rec_* counts default to 0, so a delayed connection raises, naming the field, until rec_excitatory_synapses or rec_inhibitory_synapses is written. A count written as 0 keeps the connection as a lesion and logs a message. A synapse count for a stream that no connection feeds is unused.

Probability masks and seeds

probability: p samples, at each dendritic level, a fixed Boolean mask over the target’s compartments and the source’s units, keeping each pair with probability p. A compartment left without any eligible unit of a source receives one unit drawn from that source, so a mask never disconnects a compartment from a source completely. Synapses are then selected only among the eligible pairs. Masks are sampled once, when the model is built.

The mask of a connection is seeded by its seed, otherwise by the layer’s connection_seed, otherwise by 0; dendritic-train fills an unset connection_seed from experiment.topology_seed (see Random seeds and reproducibility flags). The seed is offset by the layer, source, target, timing, pathway, level and shapes, so different connections draw different masks, and sampling uses its own generator, so it does not change PyTorch’s global random stream.

With allow_self_recurrence: false, a delayed connection from a population to itself excludes each neuron’s own output from its compartments.

Dendritic target levels

target_levels restricts a connection to some depths of the target’s dendritic tree: soma (depth 0), primary (the children of the soma, depth 1), distal (the outermost level) or explicit depths from the soma. Synapses at other depths are drawn only from the stream’s other sources. Each depth that has synapses of a stream must be allowed by at least one of that stream’s connections; otherwise the build raises. To leave a depth without synapses, set its count to 0 with *_synapses_by_level. Contacts that rewiring replaces are drawn within the same restriction. The microcircuit in Named populations uses target_levels to separate soma-targeting from dendrite-targeting inhibition.

Connection masks and structured connectivity

The population option structured_connectivity applies a structured mask to a pathway (see Structured connectivity). A stream can also have a connection mask, because one of its connections sets probability below 1 or target_levels, or because allow_self_recurrence: false applies to it. Both masks then restrict the stream: a compartment receives only contacts that both allow, and a combination that leaves a compartment without any allowed input raises. Structured rules that place exact contacts (spatial_morphology and index manifests) cannot also follow a connection mask, so combining them with one raises.

List-valued probability and indegree of a structured rule are indexed by the network layer (layers[i]), and each layer draws its own seeded masks. Layer 0 draws the masks of earlier versions; before 2026-10-11 every layer used the population’s position in its layer for both, so a population at the same position in each layer read the same list entry and drew the same mask. Training fills an unset seed of a structured rule from experiment.topology_seed (since config_version 3; earlier, unseeded masks drew from the global random stream, which seed: global_rng keeps; see Structured connectivity).

Named populations

Each entry of model.core.population_network.layers[].populations defines one named population:

Field

Default

Meaning

name

required

Name used by readout_population, connections, qualified sources, recurrent state and analysis output, for example pyr, pv or sst.

polarity

excitatory

excitatory or inhibitory. It decides which stream of a target the population’s output enters; it is not a receptor type.

n_neurons

required

Number of neurons (somata).

branch_factors

[1]

Dendritic morphology, from the soma outward: [3, 3] gives each neuron 3 primary branches with 3 children each (three levels including the soma); [] is a point neuron whose only level is the soma.

population

{}

Population options for this population only (see Options reference).

population_defaults is merged into every population of the layer, and the population’s own population block is merged on top of it (nested mappings such as synapse_types are merged key by key). n_neurons and branch_factors are set only on the population definition: writing them in population_defaults or in a population block raises. When a population sets use_shunting: false and no reactivation_init_policy, it uses occupancy_quantile (see Gate initialization and maintenance).

Distinct populations can differ in morphology, time constants, synapse counts and dynamics. A population is a group of neurons, not a receptor mechanism: to give a population AMPA and NMDA inputs, add receptor types to its options (see Receptor synapse types) instead of defining a population per receptor. Populations that differ only in receptor kinetics share their other options and set different synapse_types blocks in their population overrides.

The configuration below builds this microcircuit. The population blocks give the three populations different dendritic time constants, and target_levels separates the two kinds of inhibition:

model:
  core:
    type: population_network
    population_network:
      layers:
        - name: microcircuit
          recurrent: true
          readout_population: pyr
          connection_seed: 123
          population_defaults:
            ff_excitatory_synapses: 12
            ff_inhibitory_synapses: 4
            rec_excitatory_synapses: 8
          populations:
            - name: pyr
              polarity: excitatory
              n_neurons: 32
              branch_factors: [2, 2]
              population: {tau_base: 20.0}
            - name: pv
              polarity: inhibitory
              n_neurons: 8
              branch_factors: [1]
              population: {tau_base: 5.0}
            - name: sst
              polarity: inhibitory
              n_neurons: 8
              branch_factors: [1]
              population: {tau_base: 12.0}
          connections:
            - {source: input, target: pyr}
            - {source: input, target: pv}
            - {source: input, target: sst}
            - {source: pv, target: pyr, probability: 0.45, target_levels: [soma, primary]}
            - {source: sst, target: pyr, probability: 0.25, target_levels: [distal]}
            - {source: pyr, target: pyr, timing: delayed, probability: 0.75}
            - {source: pyr, target: pv, timing: delayed}
            - {source: pyr, target: sst, timing: delayed}
training:
  main:
    strategy: recurrent

The populations pv and sst receive no inhibitory input, so their ff_inhibitory_synapses count is unused.

Temporal constants and delays

A layer steps through time when it sets recurrent: true, when it has a delayed connection (which requires recurrent: true), or when one of its populations uses a temporal feature: a spiking soma, receptor synapse types, dendritic spikes or soma feedback (see Temporal dynamics). The whole network then processes sequences [batch, time, features]; a two-dimensional input is treated as a single timestep. output_mode: mean or all also makes the network process sequences, with feedforward layers applied at every timestep.

In a layer that steps through time, every dendritic level l of a population keeps leaky traces of its raw synaptic currents u (the four input streams and the input from child branches) and computes its voltage from the traces:

\[x_l(t) = \alpha_l\, x_l(t - \Delta t) + (1 - \alpha_l)\, u_l(t), \qquad \alpha_l = e^{-\Delta t / \tau_l} .\]

Layers that do not step through time compute the voltage from the currents directly, and the time constants have no effect. Timing has these independent controls:

model.core.population_network.layers[].dt

The integration step \(\Delta t\) of every population in the layer (default 1.0). A delayed connection always reads the previous step.

tau_base and tau_ratio

Per-level time constants when level_taus is empty: \(\tau_l = \tau_{\text{base}}\, r^{\,n - 1 - l}\) for levels l = 0 (most distal) to n - 1 (soma). The soma level uses tau_base and each level further out is tau_ratio times slower. The defaults tau_base: 50 and tau_ratio: 3 give [450, 150, 50] for a three-level population; tau_base: 20 and tau_ratio: 2 give [80, 40, 20].

level_taus

Explicit time constants, from the most distal level to the soma. The list length must equal the number of levels (len(branch_factors) + 1).

learnable_tau

Learns one time constant per level, stored as its logarithm.

connections[].timing

delayed connections read the source output of the previous step; same_step connections read the current step.

Receptor traces (synapse_types), the spiking soma (spike_tau, spike_readout_tau) and dendritic plateaus (dendritic_spike_plateau_tau) have their own time constants, which use the same dt; see Temporal dynamics.

In this excerpt of model.core.population_network, the layer integrates with a half step, pyr uses geometric time constants [80, 40, 20], and pv sets and learns its own:

layers:
  - name: circuit
    recurrent: true
    dt: 0.5
    readout_population: pyr
    population_defaults:
      ff_excitatory_synapses: 8
      ff_inhibitory_synapses: 2
      rec_excitatory_synapses: 4
      tau_base: 20.0
      tau_ratio: 2.0
    populations:
      - {name: pyr, polarity: excitatory, n_neurons: 32, branch_factors: [2, 2]}
      - name: pv
        polarity: inhibitory
        n_neurons: 8
        branch_factors: [1]
        population: {level_taus: [5.0, 5.0], learnable_tau: true}
    connections:
      - {source: input, target: pyr}
      - {source: input, target: pv}
      - {source: pv, target: pyr}
      - {source: pyr, target: pyr, timing: delayed}
      - {source: pyr, target: pv, timing: delayed}

Population options

Population options are set in model.core.population_network.layers[].population_defaults for every population of a layer, or in layers[].populations[].population for one population. The tables group them by topic. Several defaults differ from the corresponding model.core sections of structured E/I cores (Structured E/I cores): weight_transform defaults to exp here and to softplus in model.core.morphology, somatic_synapses to true here and to false there, and reactivation_init_m to 1.0 here and model.core.reactivation.init_m to 1.5. Write these options explicitly when results are compared across the two core families.

The renamed fields topk_strategy, reactivation_strategy and blocklinear_strategy still load, with a warning, as topk_gradient_scaling, reactivation_gradient_scaling and blocklinear_gradient_scaling.

A population that is stepped through time (in a recurrent layer, or with synapse types, a spiking soma, dendritic spikes or soma feedback) runs each branch layer once per time step before one backward pass. Its conductance_dynamic scales are then registered on the tensors of each step, so every step’s gradients are scaled by that step’s scales; with topk_gradient_scaling: none only the couplings keep their per-step tensors. A feedforward population applies the scales of its single forward pass through backward hooks.

Configuration choices

The table lists common choices, the library default and what to consider.

Choice

Default

Recommendation

Integration rule

use_shunting: true

Set use_shunting per population. For additive populations, set use_additive_normalization: true only when across-output normalization of the voltage is part of the model, and choose the additive rule with additive_mode (see Integration modes).

Gate initialization

analytical (occupancy_quantile when use_shunting: false)

occupancy_quantile calibrates each gate’s slope and midpoint on measured voltages before training, so the gate starts at the operating point of the data in every population and depth (see Gate initialization and maintenance).

Positive conductances

weight_transform: exp

softplus also keeps conductances positive and grows linearly instead of exponentially in the stored parameter. Structured E/I cores default to softplus, so write the transform explicitly when the two families are compared.

Developmental sparsity

topk_type: standard

dense_to_sparse trains with more active synapses at first and reduces them to the target count on a schedule.

Multilayer routing

input is the previous readout population

Qualified sources (layer0.e0, layer0.i0) make cross-layer routing explicit and can read several populations of earlier layers.

Recurrence

feedforward layers

Set recurrent: true and add timing: delayed connections; write the rec_*_synapses counts they need.

Because layer, population and connection keys are checked only when the model is built, run dendritic-train config.yaml --validate-only after editing a population network. Sweep axes address population fields by dotted paths with list indices, for example model.core.population_network.layers.0.population_defaults.tau_base (see Parameter sweeps).
